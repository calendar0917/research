Lesson 0002 · Code and experiment audit

不要先读模型，先追踪数据

审计 AI 生成的实验代码时，最有效的第一步不是理解网络结构，而是给数据标记角色，然后追踪它是否越界。

本课唯一胜利
你能看出一个实验是否遵守：训练集学习，验证集选择，测试集终评。

1. 四个动词

代码审计可以先压缩成四个动作：

  1. Split：确定哪些样本属于 train、valid、test。
  2. Fit：从数据中学习参数，例如 scaler 的均值、PCA 方向、字典原子或分类器树结构。
  3. Transform / Predict：使用已经学到的规则处理新数据。
  4. Evaluate：计算指标；这一步本身不应反过来改变模型或选择规则。

最容易犯的错误是把“没有调用模型的 fit”误认为没有学习。特征标准化、降维、字典学习、特征筛选、选择最佳权重，都可能在学习信息。

2. 读你仓库中的真实代码

在 `fit_xgboost_views` 中，关键路径是：

train = split["train"]

model.fit(matrix[train], y_train)

predict_proba(matrix[valid])

predict_proba(matrix[test])

这段结构表达了一个可审计的协议：XGBoost 只用训练集学习；验证集用来比较 view；测试集只有在 evaluate_test=True 时才评估。代码还记录了 best_by_valid_only 和 test is never used as a tie-breaker，这是把实验纪律写进程序，而不是只写在报告里。

但审计不能停在这一个函数：还要向上追问 views 是在哪里生成的。如果 KSVD 字典、标准化器或特征选择器在 split 前对全体分子调用了 fit，下游分类器虽然“只 fit train”，整个实验仍可能泄漏。

3. 一个反例

scaler.fit_transform(X_all)

X_train, X_test = split(X_scaled)

model.fit(X_train, y_train)

问题不在最后一行，而在第一行：scaler 的统计量已经看过测试样本。正确顺序是先 split，再对训练集 fit_transform，对测试集只调用 transform。官方 scikit-learn 指南将这类问题称为 data leakage，并建议用 Pipeline 让正确的数据边界更难被误写。
