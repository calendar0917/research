Lesson 0009 · Model literacy

模型作为工具：先看契约，再看机制

接口告诉你“怎么调用”；基本理解告诉你“调用了什么、结果意味着什么、什么时候不能相信”。

本课唯一胜利
读一段模型代码时，你能说清输入、输出、训练目标、评估指标和数据边界，而不必先学完模型的全部数学。

1. 一个模型调用其实有两层

接口层是 fit、predict、forward 这些入口，以及参数的名字和类型。它让代码能运行。

语义层是输入表示、输出含义、训练目标、方法假设和失败方式。它让你知道运行结果能否回答研究问题。

接口：model.fit(X_train, y_train)

语义：模型正在用哪些对象学习？X_train 是固定特征还是图？y_train 是什么标签？训练后输出是类别、概率还是分数？

科研审计通常不是从公式开始，而是先把这两层分开。公式只有在解释异常或核对实现时才需要深入。

2. 用一段 XGBoost 代码练习“模型契约”

model = XGBClassifier(
    objective="binary:logistic",
    eval_metric="auc",
    max_depth=4,
    learning_rate=0.05,
    n_estimators=300,
    random_state=7,
)

model.fit(X_train, y_train,
          eval_set=[(X_valid, y_valid)],
          verbose=False)

p_test = model.predict_proba(X_test)[:, 1]
test_auc = roc_auc_score(y_test, p_test)

先只读懂五件事：

  1. X_train 通常是 [样本数, 特征数] 的固定长度矩阵；这里的特征是否编码了分子结构，决定了 XGBoost 能利用什么信息。
  2. fit 改变模型内部状态；predict_proba 只读取已经训练好的状态。
  3. [:, 1] 取正类的连续概率/分数，不是硬分类标签；ROC-AUC 需要这样的排序分数。
  4. objective="binary:logistic" 指定训练目标和二分类输出形式；eval_metric="auc" 指定监控/报告指标。
  5. X_valid 出现在评估位置，X_test 只在最后计算结果。是否真的遵守这个边界，还要继续检查调参和模型选择代码。

这就是“作为工具的基本理解”：不必知道每棵树如何计算 gain，但必须知道代码把什么数据、什么目标和什么输出连接在一起。

3. 把同一张工具卡迁移到 GNN

输入：x、edge_index、可能还有 edge_attr 和 batch。

输出：节点级、边级或图级的 logits/概率/表示。

核心机制：节点表示通过邻接关系聚合消息；图结构不是普通列特征，而是计算路径的一部分。

首先审计：图是怎样构造的？标签或未来信息是否通过边、节点特征或预处理泄漏？readout 是否对应任务层级？

XGBoost、MLP、GNN 的接口可能都叫 fit 或训练循环，但它们接收的表示和利用的关系不同。因此“同一个 API”不代表“同一个研究假设”。

带走的研究句

模型是工具，但不是无语义的工具。
使用它之前至少要知道：它看见了什么表示，利用了什么关系，优化了什么目标，输出的数字是什么意思，以及这个数字受哪套协议约束。

打开模型工具卡，以后遇到 XGBoost、MLP、GNN 或 KSVD，都用同一张卡快速定位。
