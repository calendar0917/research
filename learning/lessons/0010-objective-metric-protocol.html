Lesson 0010 · Experiment protocol

一个分数，究竟由什么决定？

模型只是实验链条中的一环。训练目标、评估指标和数据划分，决定了一个分数能不能成为证据。

本课唯一胜利
看到训练代码或实验报告时，你能区分：模型在优化什么、研究者用什么指标做选择，以及测试集是否仍然独立。

1. 结果不是模型名字的属性

“GNN 达到 0.78”这句话少了很多条件。更完整的对象是：

结果 = f(数据, 表示, 模型, 目标, 训练, 选择规则, 划分, 随机性, 指标)

因此两个实验即使都叫“GNN vs KSVD”，只要图构造、特征预处理、epoch 选择或 split 不同，就不一定是在比较同一件事。Open Graph Benchmark 将数据集、任务定义和 split 作为 benchmark 的一部分，原因就在这里。

2. 训练目标、评估指标、选择规则

把三种角色分开，代码就容易读很多：

训练目标（objective/loss）：每次更新时，模型试图让什么变小或变大？

评估指标（metric）：我们用什么尺子描述预测好不好？

选择规则（selection rule）：多个 epoch、超参数或方法之间，依据哪份数据的哪个指标保留一个？

model = XGBClassifier(
    objective="binary:logistic",
    eval_metric="auc",
)
model.fit(X_train, y_train,
          eval_set=[(X_valid, y_valid)])
p_test = model.predict_proba(X_test)[:, 1]
test_auc = roc_auc_score(y_test, p_test)

这段代码可以这样读：

  • objective 规定训练目标和输出形式；
  • eval_metric 规定监控/比较的指标；如果它参与 early stopping，就会参与 checkpoint 选择；
  • roc_auc_score 是最后报告的测试指标；它衡量排序能力，不等于概率校准，也不自动说明机制成立。

目标与指标不同并不一定是错误，关键是报告中要说明这种关系。更多常见错误可查 scikit-learn 官方 Common pitfalls。

3. 三份数据的职责

Train：学习模型参数，以及只允许从训练数据学习的 scaler、PCA、字典或特征选择规则。

Validation：在候选方案之间做决定，例如选 epoch、超参数、特征视图、阈值或 seed。

Test：方案冻结后，尽量不再影响决策地给出最终估计。

“测试集只评估一次”是一个很好的默认习惯，但真正的原则是：测试结果不能反过来指导方案选择。若你看了 test 后改了代码、选了更好的 seed，再报告这个 test，测试集就已经参与了研究决策。

4. 两种常见的越界

# 问题一：表示和变换在 split 之前学习
dictionary = fit_ksvd_dictionary(all_graphs)
features = scaler.fit_transform(all_features)
train, valid, test = scaffold_split(features)

# 问题二：测试集参与 checkpoint 选择
for epoch in range(1, 101):
    train_one_epoch(model, train_loader)
    test_auc = evaluate(model, test_loader)
    if test_auc > best_test_auc:
        save_checkpoint(model)

第一段的风险不在“用了 KSVD 或 scaler”，而在它们的 fit 看到了哪些样本。若目标是 inductive 泛化，应该先划分，再只用 train 学习变换，valid/test 只使用已学规则。

第二段把 test 变成了选择器。即使最后只报告一个数字，它也不再是干净的最终证据；checkpoint 应依据 train 内部验证或 official validation 选择。

如果研究有意使用全图无标签预训练或 transductive 设置，也可以做，但必须明确写出这是不同的协议；不能把它和严格 inductive 结果混在一起。
