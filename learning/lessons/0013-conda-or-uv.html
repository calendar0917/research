Lesson 0013 · Reproducible environments

环境管理：conda 还是 uv？

复现实验的地基，是把“曾经能跑”变成“任何人都能确定地跑”。conda 与 uv 是两条路线，各有各的位置。

本课唯一胜利
拿到一篇新论文，30 秒判断该用 uv 还是 conda；并且说得清解释器、包、环境分别放在哪里。

1. 先把“环境”拆成三层

“配环境”其实是三件事：

环境 = 解释器（Python 3.12？） + 包（torch？）+ 位置（装在哪、如何隔离）

conda 和 uv 都提供这三件事，但由谁提供、装在哪不一样。理解这张表，比背命令更重要：

维度condauv
解释器建环境时选定，环境自带可自动下载（uv python install 3.12），也能复用系统/conda 的
包来源conda 求解器 + conda-forge 编译好的二进制pip 轮子生态 + 专用 index（PyTorch cu121/cu124、Astral GPU）
环境位置envs_dirs，默认 <conda前缀>/envs项目目录下的 .venv
系统级库
(MPI、R、mkl、旧 CUDA)		强项：这些都做成包发布几乎做不到，只能 pip 轮子
精确锁定conda export --file conda-lock.yaml 或 conda list --explicituv.lock（含哈希）
速度慢（求解器、无共享缓存）很快（Rust 实现，全局缓存复用）
无 sudo 时需要已有 conda，用 -p 隔离单二进制 curl 安装即可

这张表不是“谁更好”，而是“谁负责哪一层”。conda 官方环境文档说明 --prefix 可把环境放到任意位置；uv 官方安装 Python说明解释器自动下载行为。

2. 决策规则（30 秒）

uv：依赖都能从 PyPI 拿到轮子（torch、torch-geometric、ogb、numpy……全是的）。项目自带 pyproject.toml + uv.lock 最好。

conda：需要 conda-forge 才有的原生二进制——MPI、R 接口、特定旧 CUDA 运行时、mkl、fortran 编译库。

复现别人项目：有 uv.lock 就 uv sync；有 environment.yml 或 explicit spec 就 conda create -f。

隔离原则：永远把环境建在“自己的目录”，不要写进共享前缀。uv 天然如此（项目 .venv）；conda 用 conda create -p <path>。

两条路线在这个场景下都能干净落地，选哪条取决于团队习惯：

  • conda 路线（组内惯用）：借导师的 conda 二进制 conda create -n xxx python=3.12，环境进默认 ~/enter/envs——只要命名清晰、不动 base，共享目录完全可以接受。
  • uv 路线（习惯 pip 时更顺）：自动下载解释器、环境落在项目 .venv，与组内环境完全隔离。

共同原则：环境是实验的一部分——对复现负责任的不是“哪个工具酷”，而是你留下了 environment.yml / uv.lock 这类精确清单。

3. uv 怎么用：一个目录一个项目

# 1) 装 uv（单用户，无 sudo；装到 ~/.local/bin）
curl -LsSf https://astral.sh/uv/install.sh | sh

# 2) 每篇论文一个目录，复制已有 lock 的项目最快
mkdir -p ~/papers/attn-gnn && cd ~/papers/attn-gnn && git clone <repo> .
uv python install 3.12      # 可选：预先下载解释器（uv sync 也会自动装）
uv sync                     # 按 uv.lock 精确重建 .venv

# 3) 新项目：声明依赖，lock 自动生成
uv init && uv add torch==2.5.1 "torch-geometric==2.6.1" numpy

# 4) 什么都不 source、不 activate，直接运行
uv run python main.py

要点：不需要 source 任何脚本，uv run 自动使用项目 .venv；uv.lock 与 pyproject.toml 一起提交 git，复现 = git clone && uv sync。torch 的 CUDA 变体（cu118/cu124）通过 [tool.uv.index] + [tool.uv.sources] 指定，模板见环境速查卡。

4. conda 兜底：借二进制，不借目录

eval "$(/home/hxy/enter/bin/conda shell.bash hook)"   # 只复活函数，不改 .bashrc
conda create -p ~/papers/xxx/env -c conda-forge python=3.9 mpi4py
conda activate ~/papers/xxx/env                         # 环境在自己目录，不进 ~/enter/envs
conda export > environment.yml                         # 记录：重建时 conda create -f

conda 求解器慢，所以一次性把包列全再 create；环境里混用 pip 后，尽量“重建环境”而不是在原环境上继续 conda 操作（官方建议，见上表来源）。

5. 现在练习

服务器无 sudo，系统只有 Python 3.10，论文要求 Python 3.12，只允许你装一个工具——选哪个？

论文依赖 MPI 编译的缓存库和 R 语言接口，pip 没有现成轮子——哪条路线更稳？

三个月后同事想重建你的实验环境，哪个文件最可靠？

带走的研究句

环境是实验的一部分，不是背景。
“我用 uv.lock / conda-lock.yaml 记录了完整环境；报告的结果对应这个锁定环境，而不是‘当时能跑的机器’。”

打开环境速查卡（常用命令 + CUDA index 模板），回看实验协议速查：环境锁定和协议一样，都是为了“能被别人重建”。

Primary sources

uv: Projects：pyproject + lock + sync 的机制，优先读“Locking and syncing”。

uv: Using uv with PyTorch：torch 的 CUDA 变体与专用 index 配置。

uv: Installing and managing Python：解释器自动下载与复用规则。
