## 1. 一句话结论

在官方 `ogbg-molesol` / `ogbg-mollipo` 上，**用 Train 监督自动发现的离散结构查询没有带来
可判定的收益**：它比固定查询库 F 略好或略差（取决于任务与 split），比复杂度匹配的随机库 R
好不到 3%，并且明显落后于最强参考（molesol 上是 L=C1/NO_BOND_MEAN，mollipo 上是 G=GINE）。
但**导出/重放这条链路是通的**：查询与决策树可以逐位重放（最大绝对误差 6.4e-6 / 5.0e-6，
原始单位）。

## 3. 性能 vs 规则复杂度

- 发现出的查询：每任务 64 条；AST 节点数 2–9（中位数 4，`MAX_NODES=9` 未被顶满），
  hop 深度 0–3；算子构成里 `NBR` 占多数（89 / 101 次）、`AND` 42 / 44 次、`BRANCH` 11 / 14 次。
  例子（molesol，train_gain 最高）：`NBR(ACYCLIC,BOND_EQ(0,0),2)`、
  `AND(ATOM_EQ(2,2),ATOM_EQ(4,1))`；mollipo：`AND(ATOM_EQ(4,1),DEG_EQ(1))`。
- 头部模型规模：molesol 选 H1（depth 3, 800 棵 → 9338 节点），mollipo 选 H2
  （depth 5, 799 棵 → 37661 节点）。每棵树一条路径即一次完整判定，Val case study 里
  单分子的总路径长度是 2399 / 3985 个节点步。
- **重要**：在选中的树里，`base::n_atoms`（分子原子数）一个特征就占了全部 split 的
  54.6% (molesol) / 51.1% (mollipo)；发现查询的列合计只占 18.9% / 19.3%
  （B 库列占 26.4% / 29.5%）。这两个任务上"分子大小"是主导信号，查询列主要在纠偏。
  这也是为什么"A 只比 F 好一点点"——F 的 base 列里本来就有大小。

## 4. 为什么 H_query 是 `CONTROL_INCOMPLETE`

协议要求 R 与 A 的查询**结构一一同形**（算子计数、嵌套 hop、m=3 这类常数都不变），只把
参数（元素列取值、度、环、键型）换成 Train 词表里的随机双射，并且要求 Train 上至少 8 个
分子有匹配、特征不与已有项重复；每槽最多 512 次尝试。

molesol 64/64 填满；mollipo 61/64。三个没填上的形状枚举了整个参数空间
（`code/sq_diag_r_budget.py`，纯 CPU、只读）：

| 槽位 | AST | 参数赋值总数 | 可行数（≥8 分子） | 期望尝试次数 | 512 次内未命中的概率 |
| --- | --- | --- | --- | --- | --- |
| A033 | `AND(ATOM_EQ(0,5),NBR(NBR(ATOM_EQ(0,6),BOND_EQ(0,3),1),BOND_EQ(1,0),3))` | 1320 | 3 (0.23%) | 440 | 0.31 |
| A051 | `AND(ATOM_EQ(0,6),NBR(NBR(ATOM_EQ(0,5),BOND_EQ(0,0),1),BOND_EQ(0,3),1),NBR(NBR(ATOM_EQ(0,7),BOND_EQ(0,1),1),ANY,1))` | 23760 | 16 (0.07%) | 1485 | 0.71 |
| A055 | `AND(ATOM_EQ(0,5),NBR(NBR(ATOM_EQ(0,6),BOND_EQ(2,1),1),BOND_EQ(0,3),3))` | 880 | 4 (0.45%) | 220 | 0.10 |

结论：**不是结构上不可行，而是"512 次/槽"这个预注册预算对最深的复合形状太紧**
（每槽失败概率 10%–71%）。协议规定 R 不完整时该轴不得判定，所以这一轮 H_query 只能报
`CONTROL_INCOMPLETE`——**我没有在看到结果之后把 512 改大**，那会变成用结果挑协议。

一个**明确标注为非正式**的探索性检查（`--refit --max-attempts 4096`，本地 CPU，不进正式结果）：

- 4096 次/槽 → R 填满 64/64，形状全部匹配；
- 该完整 R：Val 0.8229 / Test 0.7672（正式 R 是 0.8019 / 0.7588，A 是 0.7911 / 0.7525）；
- 即 A vs 完整 R = −3.9% (Val) / −2.0% (Test)：Val 过 3% 线、Test 不过。

方向上是**保守的**：换成完整 R 也没有让 A 达成预定判据，所以"没有可判定收益"这个结论不依赖
R 不完整这件事；但按协议，正式判定仍然是"不可判定"而不是"无收益"。

## 5. 这张表不能说明什么

- **不是**化学因果结论。查询可在 Train 结构上被重放，不代表它们对应真实物化机制；
  导出可执行性只证明"表示是可执行的"。
- **不是** GNN vs 查询语言的比较。G 是同一划分上的一个普通参考实现；两者本轮的差距同时
  包含归纳偏置差异与调参差异，且只有一个 seed。
- **不是**多 seed 稳定性结论。单 seed（0）；bootstrap CI 只刻画重采样不确定性，不含
  seed 方差。molesol 只有 902 个训练分子，CI 很宽（±0.07 RMSE 量级）。
- **Test 是开发评估集**（`test_policy: always`，按你的指示）。选模型只用 Val RMSE；
  Test 从不参与选择，但它已经被"看过"，不能当作无偏泛化估计。
- G 的数值只代表"这个冻结配方"（5 层 GINE、360 epoch、两个 peak LR）。第一版 G 有个
  target 标准化 bug（RMSE 被乘上 Train std），已修复并重训；现在的 G 是可用的参考，
  但依然没有做超参搜索。
- `ogbg-molesol` 与 `ogbg-mollipo` 的标签本身与分子大小强相关，本轮 F/A/R 都共享这套
  base 列，所以"三者差距很小"有一半是任务性质决定的。

## 7. 如果还要往下走

按本轮结果，唯一值得做的是**先把对照和判据修好**，而不是加任务：

1. 下一轮预注册 R 的尝试预算（或改成确定性枚举 + 优先填充），让 H_query 可判定；
2. 判据要能区分"多了 64 个复合特征"与"监督选择更好"——本轮 A 与 R 的差距（−1.4% / −0.8%）
   说明现在的搜索几乎没在 R 之外找到额外信息；
3. 若要比神经参考，需要给 G/E 同样的调参预算，否则测到的是"配方"差异；
4. 想真正验证结构规则，需要把 `n_atoms` 这类全局大小特征从 base 列里拿掉，或者做
   size-matched 的分层评估，否则大小信号会掩盖结构信号。
