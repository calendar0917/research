## 2. Freshness contract

* The two arms are built from `zw.build_arm(arm)` (`build_deploy_model(None)` +
  the bridge), which loads no learned state.
* Phase A verified the fresh build reproduces the saved (untrained)
  `D_init_state.pt` / `M_init_state.pt` item-for-item (all 36 tensors each,
  0 mismatches) and that the 34 shared non-bridge tensors have the published
  hash `5a8d8ff042fff496802a64a3266a1c18caff4a132331b154bd6087e5200ba2a6`.
* No `S_M`, `A0`, `C`, `T`, `O`, `H`, `Y`, `D_y`, `M_y` trained tensor is loaded
  into `D_g`/`M_g`; only `*_init_state.pt` was considered and only because it
  was verified byte-identical to a fresh build.
* The initial D and M functions differ on the fixed fit batch (max abs diff
  `0.4010`, RMS `0.1328`); no function matching is claimed.

## 4. Bridge semantics (single insertion point)

`DeployFull.environments_masked` is the only producer of the environment tensor
consumed by the unary/pair consumers:

```
interface = Sem108(coord, data)
h = fusion(interface)               # [*, 144]
E = local_dictionary_bridge(h)      # D_g: column-normalized Dbar, 16-step ISTA
                                    # M_g: bias-free 144->288->144 SiLU MLP
```

D keeps the exact source semantics: detached solver step
`1 / (1.05 * eigmax(Dbar Dbar^T) + lambda2)`, 16 unrolled soft-threshold steps,
`E = scale * (alpha @ V_L)` with the row-RMS restoration.  M computes
`E = scale * W2 SiLU(W1 x)` with the same `scale = sqrt(mean(h^2)+1e-12)`.
No graph id, adjacency, node/edge state or readout bypass enters either bridge.

## 5. Target semantics

* `g = y - c` exactly; `c` is the label-derived cycle component in normalised
  units, not a model prediction, not an input, and not added at evaluation time.
* The cycle normalisation constants were refit on fit rows only; Phase A
  reports that no `k` label changed versus the old decomposition and that
  `c` differs by at most `0.03365` because of the constant refit.
* `G0` rows have constant `c0`; there the new g-MAE and `pred_g + c0` y-unit MAE
  are the same number, which is why the G0 four-arm comparison is legitimate.
* On non-G0 rows, y-MAE and g-MAE are different tasks; they are never presented
  as a deployment comparison.

## 6. What is matched and what is not

Matched: parameter count (82,944), input normalization, shared body and data
protocol, optimizer/loss/schedule/seed, dropout RNG stream (the bridges contain
no stochastic op and the schedule is pre-hashed).

Not matched by design: `D_g` runs 16 unrolled ISTA steps with a matrix
dictionary and no reconstruction term; `M_g` is one hidden SiLU layer.  The
comparison is between these two **function classes** under decomposed chemical
supervision, not a purified "with vs without sparsity" experiment, and
parameter matching is not FLOP matching.

## 7. What the bridge is not (luyin19 boundary)

The recording says the shared dictionary's purpose is a transferable
**structure-attribute relation** and that the open issue is structure-semantic
fusion.  This round's bridge is only the fused task-side coding after the
compressed fusion; the original structural dictionary, `U`/IHT coding and slot
binding were removed in the deploy skeleton.  A win by this bridge supports
"continue studying this task bridge under decomposed chemical supervision",
not luyin19's structural-semantic transfer claim.  A loss does not refute all
dictionaries.

## 8. Replay, determinism and mechanism probes

* Per-arm training uses the pre-hashed shared batch schedule; after training the
  raw-soup state is reloaded into a fresh arm, both fit and dev predictions are
  computed in eval mode, and a fixed 128-row batch is replayed CPU vs GPU with
  pre-fixed threshold `max abs <= 1e-5`.
* The smoke verifies shared body hashes, both bridge parameter counts, consumer
  use of the bridge output, that labels cannot change a forward, that the loss
  is exactly `L1(g)` (and differs from `L1(y)`), endpoint offsets, real
  optimizer updates, and a tiny g training with matching schedule.
* Mechanism probes are read-only diagnostics on a fixed fit batch (init/soup,
  isolated RNG) plus full fit/dev representation statistics; they never update
  training state and no dev backward is taken.  Gradients are only taken
  against fit `g`.
