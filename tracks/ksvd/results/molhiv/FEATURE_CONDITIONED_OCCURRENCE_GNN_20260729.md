# 节点特征驱动的局部片段图实验（2026-07-29）

## 1. 这次要回答什么

这轮实验对应下面的结构：

```text
原始原子和化学键
→ 一层轻量原子消息传递
→ 按 prototype 的连通命中区域组成 occurrence（局部片段实例）
→ 在 occurrence 之间做一层消息传递
→ 图级预测
```

目标不是再堆一个完整 GINE，而是检查三个更具体的问题：

1. 原始节点和化学键特征是否能真正进入局部片段表示；
2. 局部片段之间的连接关系是否有额外价值；
3. prototype 只是用来划分局部区域，还是它的“类别身份”本身也重要。

开发阶段只使用 8,000 图子集中的 6,400 个 official-train 图，并在其中做三个固定的 scaffold folds。official valid/test 没有编码、没有预测、没有读取标签。

实现：

- `tracks/ksvd/code/run_molhiv_feature_conditioned_occurrence_gnn.py`

结果：

- `feature_conditioned_occurrence_gnn_fold{0,1,2}_seed0.json`
- `feature_conditioned_occurrence_no_proto_fold{0,1,2}_seed0.json`

## 2. 模型如何使用节点特征

每个原子先使用完整的 OGB AtomEncoder 编码；需要原子消息传递时，再经过一层带化学键编码的 GINE。

每个 occurrence 是“某个 prototype 在分子中的一块连通命中区域”。它的表示包括：

- 区域内原子状态的匹配权重均值；
- 区域内原子状态的匹配权重最大池化；
- prototype 身份；
- 区域大小和匹配强度；
- 区域内部的真实化学键类型统计。

两个 occurrence 之间如果共享原子，或它们的成员原子之间存在真实化学键，就建立上层边。边特征记录共享数量、连接键数量和真实化学键类型。

因此这里不是只把节点特征做成全图统计量，而是让节点和键特征决定每一个局部片段的内容，并让这些片段按照分子中的真实关系交换一次信息。

## 3. 五个匹配消融

| 模型 | 原子消息传递 | occurrence 消息传递 | 三折 held-out AUC | 均值 | 参数量 |
|---|---:|---:|---:|---:|---:|
| `atom1_pool` | 1 | 0，直接原子池化 | 0.671579 / 0.602476 / 0.757370 | 0.677142 | 19,243 |
| `atom0_occ_mil` | 0 | 0 | 0.645546 / 0.678581 / 0.760857 | 0.694995 | 34,202 |
| `atom0_occ_gnn` | 0 | 1 | 0.727376 / 0.609047 / 0.714416 | 0.683613 | 43,403 |
| `atom1_occ_mil` | 1 | 0 | 0.624845 / 0.665445 / 0.727073 | 0.672454 | 40,963 |
| **`atom1_occ_gnn`** | **1** | **1** | **0.705943 / 0.661611 / 0.796310** | **0.721288** | **50,164** |

### 3.1 最关键的匹配比较

`atom1_occ_gnn` 相对直接原子池化：

```text
fold 0: +0.034364
fold 1: +0.059136
fold 2: +0.038940
mean:   +0.044146，3/3 folds 提升
```

这说明在同样有一层原子 GINE 的情况下，把原子组织成局部片段，再在局部片段之间传播一次，确实比直接把原子池化成整图表示更有效。

但两个模块单独使用时并不稳定：

```text
atom1_occ_mil − atom0_occ_mil:
mean = -0.022540，0/3 folds 提升

atom0_occ_gnn − atom0_occ_mil:
mean = -0.011382，1/3 folds 提升
```

也就是说：

- 只把一层原子 GINE 塞进片段池化，效果反而下降；
- 只做片段之间的传播，也没有稳定提升；
- “原子特征先局部更新”与“局部片段再交换信息”同时存在时才出现明显增益。

这更像一种交互作用，而不是某个单独模块本身足够强。

## 4. prototype 身份是否重要

新增匹配对照 `atom1_occ_gnn_no_proto`：

- occurrence 的划分完全不变；
- occurrence 上层图完全不变；
- 原子和化学键特征完全不变；
- 唯一变化是不给模型 prototype 的离散身份。

| 模型 | Fold 0 | Fold 1 | Fold 2 | Mean |
|---|---:|---:|---:|---:|
| `atom1_occ_gnn` | 0.705943 | 0.661611 | 0.796310 | **0.721288** |
| `atom1_occ_gnn_no_proto` | 0.608455 | 0.610009 | 0.747671 | **0.655378** |
| 有身份 − 无身份 | +0.097488 | +0.051602 | +0.048639 | **+0.065910** |

有 prototype 身份的版本在 3/3 folds 都更强，平均提升约 `+0.0659`。训练集 AUC 均值也从无身份版本的 `0.8011` 上升到 `0.9164`。

这说明 prototype 在当前模型中不只是一个“把原子分组的工具”。如果只保留分组结果，却不告诉模型每块区域属于哪一种局部模式，不同化学语义的片段会被当成同一类对象，模型明显难以利用这些局部区域。

需要注意：这不能证明离散 ID embedding 是最好的表达方式。它只证明“局部片段是什么”这类信息很重要。下一步可以用 prototype 自身的连续 PCA64 向量替代自由 ID embedding，使相似 prototype 的表示也相近，并减少对某一个词表编号的依赖。

参数统计方面，no-prototype JSON 中的名义参数量仍为 50,164，因为脚本为了保持其余层相同而保留了一个不参与前向计算的 32×40 embedding 表。真正参与计算的参数约为 48,884。

## 5. 当前能够保留的结论

### 正结论

1. **节点和化学键特征不是只能做全图统计。** 它们可以先形成局部化学环境，再进入上层片段关系。
2. **浅层的两级结构值得保留。** 一层原子传播加一层片段传播，稳定强于一层原子传播后直接池化，平均提升 `+0.0441`，3/3 folds 一致。
3. **局部片段的语义身份很重要。** 删除 prototype 身份后平均下降 `0.0659`，3/3 folds 下降。
4. **不需要深层 GNN 才能看到该信号。** 当前只有一层原子传播和一层片段传播。

### 负面限制

1. 最强配置的内部三折均值只有 `0.7213`，仍低于已有 broad occurrence / PrototypeMIL 强基线约 `0.7557`。
2. 三折结果为 `0.7059 / 0.6616 / 0.7963`，fold 间波动仍然很大。
3. 训练 AUC 均值约 `0.9164`，held-out 均值约 `0.7213`，泛化差距约 `0.1951`。
4. 50,164 参数虽然没有“爆炸”，但作为独立预测器，它需要重新学习已有 PrototypeMIL 已经掌握的主要信号，参数使用效率不够好。

因此，这轮证明的是一个**有机制意义的分支**，还不是一个可以直接取代当前强基线的模型。

## 6. 是否进入 official valid/test

**本配置暂不进入 official valid/test。**

原因不是 valid 不能用于调参，而是这个独立模型还没有超过 official-train 内部的强基线。现在消耗 official valid，只会验证一个内部证据已经显示偏弱的候选。

合理的使用顺序仍然是：

1. official-train 内部 scaffold folds 做架构和机制筛选；
2. 只把少数明显通过内部 gate 的候选送到 official valid；
3. 用 valid 在这几个候选中选择最终配置；
4. 配置冻结后只在 test 做终局评估。

## 7. 下一轮最有针对性的模型

不再让这条新分支独立承担全部预测，而是：

```text
冻结已有 strong PrototypeMIL / broad occurrence base
+
一个小型的 feature-conditioned occurrence-GNN correction
```

其中 correction 只负责修正 base 没有覆盖的信息：

- 输入使用原子、键和 occurrence 关系；
- prototype 身份优先改为 prototype 的连续 PCA64 表示，而不是自由 ID；
- correction 的隐藏维度、参数量和最大 logit 改变量都严格限制；
- base 完全冻结；
- 同时保留 `no-prototype`、无 occurrence 边等匹配对照。

这比继续加深 GINE 更合理：它保留已有约 `0.7557` 的强基础，只检查新发现的局部结构信号能否带来小而稳定的补充。
