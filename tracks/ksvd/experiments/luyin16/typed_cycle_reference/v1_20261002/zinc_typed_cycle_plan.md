## 为什么选择闭合的化学对象

现有 Sem108 按 shell 汇总化学统计；φ65 和 pair 的关系通道主要表达无类型结构。全图 topology25 已有环长度、环基和其他拓扑统计，所以再次添加无类型环计数不是一个充分的新对象。

带类型环对象保留“哪些原子、哪些键，按什么顺序出现在同一个闭合路径上”。它可以补充 shell 边际统计无法恢复的闭合化学组合。这个动机还没有被证明是当前 ZINC 误差的主因。

历史上环 token 条件化做过负实验。新方案不使用每种完整环的独立 embedding 或词条，而用共享函数处理原子和键的序列，以避免罕见环的查表记忆和 OOV。HierRelation 替换整个旧骨干的负结果也提示：本轮保留 Small 的全部有效骨干，只增加一种对象。

## 已完成的方案—验证迭代

验证代码只依赖 NumPy/SciPy，是源码推导的参考计算，不是仓库 PyTorch 模型的真实执行。

| 提议 | 轻量结果 | 决定 |
|---|---|---|
| 无类型环数量/长度 | 反例两图完全相同；仓库已有类似信息 | 不单独购买 |
| 对环序列先做线性编码再取平均 | 六环中排列不同但原子组成相同的例子，平均表示相同 | 不采用该压缩次序 |
| 每个定向环先经过非线性共享编码，再平均，再进入任务字典 | 分辨两个完整图反例及环序列排列反例；不变性和梯度参考检查通过 | 保留为唯一候选 |

完整图反例是同一个立方体拓扑的两种键型分配。所有节点原始 Sem110 相同；无类型结构相同；普通原子对×键类型总数也相同。四环中的双键数分别为 `[0,0,2,2,2,2]` 与 `[1,1,1,1,2,2]`。

源码推导的 Small/Full 参考预测差 ≤8.4e-17，新环对象字典汇总差为 0.01472。旋转、反向、20 次重标号和分图计算的差均在数值精度内；新增读出列置零时旧函数严格包含。两图未必具有不同的 penalized-logP 标签，所以这个结果只证明表示盲区与修补能力。

## 单体架构

从原始带类型图提取长度 3–10 的所有无弦简单环，去重后为每个环生成全部旋转和反向视图。每个视图由原子类别、出边键类型、位置 mask、环长度组成，共 338 维。

`338 → 64 → 48` 的共享 MLP 先编码各视图，再在一个环内部取平均，得到 48 维对象。环对象与节点环境共用现有 `D_L[48,96] / V_L[96,48]` 和相同的 16 步软阈值编码。编码迭代只求解单个静态对象，不在图上传播状态。

所有环的解码值做 sum 与 sum-of-squares 汇总，按现有 C6 习惯附加一个零化 count 槽，得到 97 维。它与原 Small 的 302 维图描述拼接，进入同一个 `399 → 13 → 13 → 1` 读出。新增读出列从零开始，旧参数和旧函数保留。

参数预算：106,925 + 环编码器 24,816 + 新增读出 1,261 = **133,002**；不新增一套任务字典。没有节点写回、消息传递、Transformer 或双模型预测平均。模型统一性来自“不同静态对象 → 同一任务坐标 → 同一个图级读出”，并不要求所有原始对象的输入维度相同。

## 先检验是否值得训练

本包提供一次便宜的官方 train-only 原始特征检查，避免直接再购买一轮 320 epoch。

- 三个按分子分组的外层折；每折内部固定 dev，分别选择三档 ridge 正则。官方 valid/test 不参与。
- 两臂都包括旧原始图特征、无类型环统计，以及普通原子对×键类型计数；第二臂才增加带类型环的组合/排列描述。
- OOF MAE 改善 ≥0.003 且至少两折改善，才购买一个 Small+ring 的正式 seed-0 训练。
- 此门是计算预算筛选规则，既不证明字典模型会获益，也不证明负结果排除了所有环表示。

这里已验证检查器能识别合成正信号，并在零新增信息时报告零收益；真实 10k 训练集检查尚待执行。

正式训练保持现有 320 epoch / Top-5 soup 协议，只跑一个候选。≤0.115 才算值得后续确认的绝对性能信号；0.115–0.120 是有限信号，不再扩容；>0.120 关闭本配置。所有历史成绩只作为背景，不能代替匹配比较。完整执行细节见 `zinc_typed_cycle_agent_prompt.md`。

## 边界

本轮还不回答稀疏码是否更优，不承诺接近 0.06–0.07，不把环通道的消融损失当作性能增益。若便宜检查无性质信号，就立即结束这次购买，不再堆 ring 变体；下一轮应重新审计任务相关信息或学习目标。
