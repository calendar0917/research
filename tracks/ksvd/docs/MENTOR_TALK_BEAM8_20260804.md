## 开场（1 分钟）

老师好。上次讨论您给我布置了两件事：

1. **先把图本身做好**，先不要拿下游任务去衡量采样好坏；
2. 解决 **patch 怎么连续、相邻、重叠**，以及 **patch 之间的位置关系**怎么表达——像图像 patch 那样能把整张图连续拼起来。

我这两周就是围绕这两件事做的。现在给您汇报：patch 构造这条线已经走通了一个方案，我们叫它 **Beam8**。另外您上次提到的几个问题——01 分解、随机游走、读出——我分别有结论。我按您提问的顺序讲。

## 第一部分：评估标准——按您的要求，改成"图本身"

**【对应 luyin12：IMDB 任务本身有问题，不要完全拿去做下游；最重要是把图本身做好】**

您上次说：IMDB-B 理论上限只有 80% 多，因为有些图同构但标签不同；全联通的图节点边都一样但类别不一样，任务本身就有问题。我回去确认了这个判断，**所以现在全部实验不再用下游分类衡量，只用图本身的三组指标**：

| 指标 | 含义 |
|---|---|
| 覆盖 | 采样到的真实边比例、节点对比例 |
| 重构误差 | 把 patch 拼回全图，observed/full RMSE |
| 稳定性 | 节点重编号后，表示是否不变 |

实验图都是按您说的规格生成的：**50 个节点、平均度 15/20/25**，regular / small-world / block 三个图族，72 张图，3-fold 图隔离，训练图不参与测试图编码。

【口头补充】您说这种密度的图单纯一次 KSVD 效果不一定好——最后的结果证明，问题确实不在 KSVD 本身，而在 patch 的质量。这个后面细讲。

---

## 第二部分：连续重叠 patch 能构造吗？——三个直觉方案都失败

**【对应 luyin12：patch 要连续、重叠、相邻，像图像 patch 一样】**

我先试了三种最直觉的做法，全部失败，但失败得很有信息量：

| 方案 | 边覆盖 | 失败原因 |
|---|---:|---|
| 独立随机游走 | 0.588 | 连续性为 0，patch 散落 |
| sliding walk（滑窗） | 0.518 | 连续了，但稳定降低覆盖——总在已看过的地方打转 |
| local frontier（沿边界扩张） | 0.598 | 在 block 图上**滞留单一社区**，出不去 |

**教训：连续性是必要不充分条件。** 您要的"能连续拼起来"只是约束，真正的目标是在连续约束下**尽可能多地看到真实边**。这三轮告诉我：必须主动引导链跨区域，而不是被动扩张。

---

## 第三部分：target-edge bridge——第一次实质性进展

**【对应 luyin12：两个 patch 之间要有重叠，patch 要能把图连续划分出来】**

第一个有效机制：**上一 patch 的边界上找一条还没被覆盖的边，作为"桥"走过去**。有点像在社区之间搭桥。

| 指标 | frontier | target bridge |
|---|---:|---:|
| 边覆盖 | 0.598 | 0.689（+0.091） |
| block 图边覆盖 | 0.584 | 0.685（+0.101） |
| 连通性 | 0.862 | 1.000 |

跨区域问题解决了。但我在 18 节点小图上做了**穷举 oracle**（每一步枚举所有合法下一 patch），发现 target bridge 离"边际最优"还有 0.138 的覆盖 gap——**"选一条目标边再走过去"没有高效用满下一张 patch 的容量**。它方向对，但搜索策略粗糙。

---

## 第四部分：Beam8——用候选搜索代替单条目标边（核心方案）

**【对应 luyin12：随机游走只是一种实现方式，不一定非得用它，你自己考虑怎么做】**

您当时说随机游走不好可以换。我们换掉了。Beam8 每一步这样做：

1. 枚举上一 patch 的 **3 节点重叠组合**（必须连通）——这就是您说的"两个 patch 之间要有一部分重叠"；
2. 按"这些节点通向多少**未覆盖边**"的边界势能，筛出 **8 个候选**；
3. 每个候选沿图边界贪心补满成完整 patch；
4. 按 **新边 → 新节点对 → 新节点 → 诱导边** 的字典序目标，选最优的下一 patch。

结果（同一批 72 张图、同样预算）：

| | target bridge | **Beam8** |
|---|---:|---:|
| 边覆盖 | 0.765 | **0.873**（+0.108） |
| RAW 全图 RMSE | 0.305 | **0.220**（−27.8%） |
| 单图耗时 | 0.025s | 0.28s（贵 11 倍，但绝对值小） |

三个随机种子全部复现（+0.108/+0.109/+0.109）。为什么是 8 不是 32：B32/R2 只再多 1.1 个覆盖点，慢 6.6 倍——预注册的 knee 规则选的 8。

**代价也明确**：pair coverage 降了 3.2 个点——Beam8 更偏向观察真实边，而不是广泛观察"非边"对。如果后续任务需要判别非边，这条要记着。

---

## 第五部分：端到端误差预算——收益来自采样器，不是解码器

**【对应 luyin12：这种 50 节点度 15–25 的图，单纯一次 KSVD 效果不一定好】**

您这句话我验证了，但结论要修正一下：**KSVD 本身是健康的**，同样 K24/T3 字典下，Beam8 的 patch 让 KSVD 全图 RMSE 从 0.416 降到 0.335（−19.5%），F1 从 0.821 到 0.878。

| 管线 | full RMSE |
|---|---:|
| 旧 target 链 + KSVD + 补全 | 0.3845 |
| **Beam8 + KSVD + 补全** | **0.3241**（−15.7%） |

然后我做了一件事：**把误差预算拆开**，看每个环节贡献多少：

| 环节 | 贡献 |
|---|---|
| 采样器换成 Beam8 | **主要收益**（−27.8% RAW） |
| slot 可靠性加权 | +0.03%，**几乎无效，已删除** |
| 线性 transition 解码器 | 无效（后面详述） |
| train-only 结构补全 | 小但可重复（−0.011） |

结论一句话：**先让连续采样器选择信息密度更高的 patches，比在旧 cover 上继续加排序、解码器、拼接的启发式都有效。** 这就是您说的"把图本身做好"的最大一块。

---

## 第六部分：patch 之间的位置关系——三次尝试，三次失败，但方向明确了

**【对应 luyin12：我们只能知道两个 patch 重合；图不像图像有连续语义；唯一排序不够，要有关联性】**

这是您最关心的问题，我花了最多时间。**先说结论：图没有图像那种"猫的眼睛→嘴"的连续语义，强行造绝对位置是行不通的；正确做法是保留 patch 之间的显式对应关系，让模型自己用。** 三次失败证据：

1. **slot-persistent（强制共享节点保持同 slot）**——最接近图像直觉的方案：
   - 一致性 +10.9%，但重构 RMSE **恶化 11.7%**，F1、覆盖全下降。
   - 原因：把不同时间步里不同结构角色混进了同一个线性坐标。

2. **显式 transition map 喂线性解码器**：
   - 正确上下文 vs 打乱上下文有 +1.0% 的方向性信号，但低于 2% gate，且绝对重构反而变差。
   - 说明：**对应关系里有真信息，但简单线性读取用不上。**

3. **拉普拉斯谱排序（Fiedler 坐标当绝对位置）**：
   - 72 张图里 5 张高密度 block 图重编号后 rank 完全 replay 不了——谱坐标有 tie，无法无歧义地区分所有节点；
   - 即使忽略 tie，重构 RMSE 恶化 0.64%。
   - 注意：这不否定 Graph Transformer 里的 LapPE（它不要求唯一排序，用多个特征向量 + 符号处理），但证明"谱坐标 = 唯一绝对坐标"这条路在图上不成立。

**【口头补充】您当时说"排序规则再多只能保证唯一，不能保证关联"——三组实验全部支持这个判断。所以我们的表示里保留了 transition map（精确记录共享节点 slot 对应）+ 固定重叠 + center 距离，但不把它压成唯一排序。**

然后我做了个更强的验证（第 9 轮）：**masked-patch 预测**——把目标 patch 整个藏起来，用其他 patch 预测它的结构：

| 分支 | masked RMSE |
|---|---:|
| patch bag（无序） | 0.224 |
| bag + KSVD | 0.189 |
| **bag + 正确关系** | **0.119**（−37%） |
| bag + 打乱关系 | 0.140 |

**正确关系比打乱关系好 15.1%**——证明 overlap/distance 绑定不是装饰，是真信号。后来把 token 换成不读编号的 ID-free 描述符，relabel 稳定性从 0.695 升到 0.998，关系增益依然在（+12.6%）。

## 第七部分：排序与置换不变性——rooted canonical 的最新进展

**【对应 luyin12：置换不变性；WL 标签聚合会丢掉最基本的语义；多规则排序只能保证唯一】**

您说 WL 标签聚合把 patch 变成"WL 表情"，丢掉语义——我试过，确认如此，已弃用。

现在的方案（第 11 轮）：**以 patch center 为锚点做精确 canonical 排序**，保留完整 45D 邻接，不丢任何结构信息。

| 分支 | 重编号后 vector 匹配 | observed RMSE |
|---|---:|---:|
| numeric ID 排序 | 0.031 | 0.370 |
| 结构签名排序 | 0.914 | 0.317 |
| **rooted canonical** | **1.000** | **0.312**（比 construction −10.3%） |

两个结论：

1. **canonical 排序同时修好了稳定性和重构**——这回答了您"排序规则能不能救"的问题：结构规则可以，但必须是精确 canonical 化，签名排序有一半 patch 有 tie，不够。
2. **边界**：结构完全等价的节点（automorphism）不存在纯结构唯一身份——48.8% 的 patch 有这种情况，这是图的本质，不是实现 bug。另外重编号后**重新采样**，patch 集合本身会变（这是采样器的等变性问题，下一步再解决，重构质量不漂移）。

## 第八部分：01 分解 / 字典原子有意义性

**【对应 luyin12：能不能让字典原子本身有意义（0/1 分解）；随机游走会破坏原子】**

您当时问能不能还原出 0/1 的原子，而不是 0.7/0.3 的小数。我在生成图上做了专门实验（用三角形、正方形生成图，看 KSVD 能否还原）：

1. **可以还原，但依赖初始化**：50 次初始化只有 58% 严格还原（atom cosine ≥0.99）；但多启动按最低训练误差选模型，R=5 时成功率到 99%——**这是可管理的局部最优问题**，不是方法不可行。
2. **随机游走确实会破坏原子**：三角形被游走多走出一条边就变形成功不了——这正是 v2 **弃用随机游走**的第二个理由（第一个是覆盖差）。
3. 一句话：**Beam8 的结构引导采样 + 多启动 KSVD，比"随机游走 + 单次 KSVD"更接近您要的"有意义原子"叙事**；但真实图上原子是否可解释，要等真实数据。

## 第九部分：读出——按您的意见后置，但有一句警告

**【对应 luyin12：max/mean/avg 读出退化成直接统计图，不如直接统计；读出后面解决，现在最重要的是图本身】**

按您说的，读出没花大力气，只做了一个归因审计（第 12 轮），结论对后面有指导意义：

- 在合成目标（图族 × 度）上，**直接统计（度分布、谱、密度、三角密度）显著胜出**所有 KSVD 读出（joint acc 0.800 vs 最好 0.580）；
- KSVD 压缩反而**降低**了关系机制的增益（0.580 → 0.453）。

这不是坏消息，是提醒：**真实数据到位后，直接统计必须作为强制 baseline 一起跑**，否则说不清 KSVD/关系机制到底贡献了什么。

---

## 第十部分：边界与下一步——需要您支持的两件事

**【对应 luyin12：我给你一批数据（50 节点、平均度 15–25）；后面做同尺寸矩阵化 + Transformer 基础模型】**

当前所有结论都来自合成图，三件边界事：

1. **等您的真实 50 节点数据**。收到后直接跑冻结审计（覆盖 → RAW 拼接 → KSVD 压缩 → 补全），不需要重新设计协议。有一个问题需要您确认：**真实数据里，不同图的节点是否共享身份？**（同尺寸不等于身份对齐——如果共享，必须加"整图对齐邻接"baseline，patch 方案要正面和它比。）

2. **矩阵化 + Transformer 基础模型**：substrate 已经就绪——ID-free patch token + overlap/distance 关系，重编号稳定性 0.998，masked 预测验证过关系信号。**但真正的 Transformer 训练还没做**，这是接下来和师兄一起的主要工作。

3. **严格等变性**：重编号后重新采样，patch 集合会变（重构质量不漂移）。如果要表示级严格等变，下一步是采样器 canonical 化或多采样集合聚合，不再改 slot 排序。

---

## 结尾：想和您讨论的三个问题

1. 真实数据的**节点身份**是否跨图共享？这决定要不要加整图邻接 baseline；
2. "patch 关系不压成排序、直接以 transition map / 距离喂给模型"这个路线，您怎么看？我的证据偏向它，但和"图像式绝对位置"的直觉相反；
3. 读出：合成数据上直接统计赢了，真实数据上我计划把 `直接统计 / raw 关系 / KSVD 关系` 三路并列跑，作为后续所有模型的公共 baseline——您觉得合理吗？
