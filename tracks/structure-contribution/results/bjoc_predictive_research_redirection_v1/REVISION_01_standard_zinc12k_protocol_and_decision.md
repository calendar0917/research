## 2. 证据重读：分清"更多有标签样本"与"更多无标签 SSL 结构"

原 `RESEARCH_PROPOSAL.md` §2/§3 B4 用样本效率证据为 H-COVER 提供正面先验。
该推理存在一步跳跃：**有标签样本数量的证据不能直接证明无标签结构覆盖的机制**。逐条更正：

| 已有数字 | 它实际证明的是 | 它不能证明 |
|---|---|---|
| `N8−N4 = −0.037304` [−0.043517, −0.031045]（同更新数，两 seed 同向） | **有标签**训练分子数（8k vs 4k）是当前最有效的杠杆；模型受标签数据限制 | 增加**无标签**结构会带来同类增益；4k→8k 是标签行增加，不是 SSL 语料增加 |
| 4k 拟合更好（fit 0.029 vs 0.040）、泛化更差（0.147 vs 0.110） | 数据受限的泛化缺口；容量不是瓶颈 | 缺口可由额外结构补上（额外结构不增加标签） |
| `P−B = −0.015653`（valid）/ `−0.020670`（exposed test） | **同一批 10k 结构**的无标签自监督确实改善了初始化；结构侧信息在 10k 内仍有可用价值 | 超出这 10k 的新结构会有增量；这是"同数据再利用"效应 |
| 曝光饱和（96.8 exposures/molecule、bond acc ≈0.995、plateau by ~visit 80） | 同目标、同语料的**重看次数**已饱和 | 语料扩大是否有效（该变量从未在主协议内被测量） |
| full10k 报告 §5 "8k→10k 的增益来自数据多样性而非曝光" | 是该报告的**跨轮、跨 split、跨基线**解释（8k 是内部 split 的标签行，10k 是 official-valid） | 同轮干净对照；且其"多样性"指**有标签行**，与无标签覆盖无关 |
| 跨任务 Lipophilicity `−0.08904` RMSE（5/5 seeds） | SSL 在**该任务自己的 3,360 个训练结构**上有效（无外部分子） | 外部无标签结构对 ZINC-12k 的价值 |
| `bjoc_predictive_bottleneck_v1` 结论 `SAMPLE_EFFICIENCY_BOTTLENECK_SUPPORTED` | 瓶颈在**标签数量/标签空间覆盖**一侧（10k 上限，协议内不可扩） | 无标签结构覆盖是同一瓶颈的可替代部分 |

**更正后的判断**：
1. 已确认的限定轴是**有标签分子数**；它在标准协议内不可增加（禁止外部标注数据）。
2. 已确认可利用的无标签杠杆是**对同一 10k 结构的 SSL 再利用**；该杠杆已实现
   （masked SSL），且其曝光维度已饱和。
3. **"增加 SSL 结构覆盖"在标准协议下已无可变空间**；H-COVER 的正面前提在此协议下不成立，
   它只能作为"额外无标签数据场景"的独立假设存在（§6）。
4. 因此 §3–§5 的重新判断只在主协议内进行。

## 3. 允许评估的问题：图级结构表示分布是否被现有汇总压缩？

### 3.1 已知冻结事实（label-blind，均来自现有报告）

| 事实 | 数字 | 来源 |
|---|---|---|
| B1 条件性代数盲区 | 固定 per-bond 表示与 junction 计数时，Null 分组对 Junction→Bond 归属不可区分（worked example Null `[3,3,3,3]` vs Organized `[2,4,3,3]`） | `results/bjoc_junction_sufficiency_audit_v1/REPORT.md` §B1 |
| B2 层析审计 | reader 输入 321 维；composer-sum 从其余块可预测 R² 0.536（最不可压缩），但**有效秩 27.9（d90=4）**；junction moments 使 composer 秩 32.4→27.9（"更共线，不是更丰富"）；`atom_sq` 线性冗余 R² 0.927 | 同上 §B2 |
| B3 真实分子近邻扫描 | 10k train 上 0 组跨分子精确碰撞；最近不同分子 reader 距离 **3.35**（Fit 独立对 p01 14.26 / median 22.59）→ 表示确实强压 | 同上 §B3 |
| B3 的位置 | 该审计明确把"近邻对造成性质误差"列为**未主张** | `STRUCTURAL_INFORMATION_AUDIT.md` §7 |

### 3.2 本轮新增检查（只读，official-train 标签，无模型前向）

对 B3 报告的 20 组最近不同分子对，读取它们的 **official-train** 标签（训练标签，非评价标签），
检查"被压缩的结构"是否携带不同目标：

| 统计量 | 近邻对（20 组） | 随机对基线（seed 0，20,000 组） |
|---|---:|---:|
| `mean |Δy|` | **0.411** | 2.108 |
| `median |Δy|` | **0.374** | 1.639 |
| `p90 |Δy|` | 0.817 | 4.465 |
| `max |Δy|` | **1.051** | — |
| `|Δy| > 0.5` 的组数 | 7 / 20 | — |

* 10k train y 范围 [−42.04, +3.80]，std 2.011。
* 20/20 组的冻结 P3 预测差与标签差一致（`pred_abs_diff ≈ |Δy|`，范围 0.024–1.051），
  即模型在这些训练行上没有混淆这些近邻对（这与训练拟合一致，不是泛化证据）。
* 工件：`results/bjoc_predictive_research_redirection_v1/b3_near_pair_train_label_check.json`
  （记录源工件 sha256、方法、20 组明细、基线、caveat）。按仓库惯例 `tracks/*/results/**/*.json` 为本地工件（git-ignored），
  本文件中的表格即为持久记录。

**解读**：目前测得的表示压缩主要把**目标相近**的结构压在一起（近邻对的 |Δy| 中位数只有随机对的 ~23%），
没有观察到"压缩导致标签不一致"的证据，且行数外的候选对被限制在 ≤200 的签名排序预算内（caveat 已记录）。
B1/B2 说表示确实丢失信息（归属、有效秩、共线性），但这些信息到目前为止没有转成可测的标签相关损失。

### 3.3 为什么这不能支撑一个新机制实验

1. **任何修复都是"新增汇总通道"**：二阶矩/分位数/pooling/注意力/set transformer
   —— 与已多次匹配否定的族同构（STRC、GLRC、DLP、cross-bond q、E type-pool、distance pooling、Soft5）。
2. **信息上近乎冗余**：`atom_sq` 可由其他块线性预测 R² 0.927；junction moments 只把 composer 变得更共线
   （秩 32.4→27.9）；"分布形状"信息在 B1 盲区中被证明不可由 Null 聚合恢复，但四个独立干预
   （O/S/GLRC/Organized/D）都无法把它转成 held-out 增益。
3. **与已有方法无明确区别**：加统计量/池化算子是标准做法（DeepSets/Set2Set/Janossy 类），
   不构成"与已有方法有明确区别"的机制。
4. **用户的约束**：不得默认新增二阶矩模块；本节只是评估，不产生推荐。
5. **反证强度**：若这是主瓶颈，至少一个同类干预应稳定为负；实际全部为正或跨零（`EVIDENCE_MAP.md` §2）。

**结论**：分布压缩是**真实但（截至目前）无害的表示性质**；不构成一个"真正改变模型可用预测信息
且尚未被充分检验"的候选机制。若未来要把它升级为证据，需要先在**未暴露 split**上证明
"近邻对系统性错分且无法由标签噪声解释"（需新预注册与标签读取授权）——那是诊断，不是本提案。

## 4. 标准 ZINC-12k 下逐一裁定：没有可推荐的新机制

| 候选 | 裁定 | 依据 |
|---|---|---|
| H-COVER（扩 SSL 语料 50k/220k） | **移出主协议**：额外无标签数据场景的独立备选假设，本轮不授权 | §1、§2、§6 |
| 新的 SSL 目标 / pretext 搜索 | **关闭**（不得重开） | 现有 masked atom/bond CE 已到 bond acc ≈0.995、CE plateau（同目标曝光饱和）；TA-SSL（监督期任务自适应掩码）已测无增益（+0.000083，4.2× 成本）；任何新 pretext 都会落回同一上下文重建族，且用户明确禁止 SSL 目标搜索 |
| Junction ownership / incidence 组织 | **关闭** | 同轮匹配对照均未取得稳健增益：O−N +0.00301（CI 跨零）、O−S −0.00199（CI 跨零）、GLRC +0.0012（Locked 符号翻转）、Organized 0.108399 vs N 0.103423、D 直接读出 −0.0028（seed 翻转）、E type-pool −0.0017；algebraic blindness 确认为表示性质但不转化为预测 |
| 固定结构签名 / 词表统计 | **关闭** | `INCONCLUSIVE` → 永久关线（含 context 扩展、k=1/k=2） |
| 结构加性残差 / 输出校准 | **关闭** | STRC 永久停止；"count-conditioned scale calibration" 是同一族（Route B 已被明确拒绝） |
| pair 乘积 / 距离条件通道 | **关闭** | DLP、cross-bond q、RW 多步、Soft5、三体算子全负或 CI 跨零 |
| 读出 scale-separation / 二阶矩 | **不默认开启**；低先验 fallback，但没有证据支持它改变可用信息（intensive 统计可由 Σ 与 n 导出；atom_sq 近冗余） | §3.3；用户明确约束 |
| 输入特征扩展（立体/电荷/氢/3D） | **不推荐**：改变标准协议可比性；非机制差异（任何模型都可加特征）；无证据指向该缺口 | 输入可观测性审计列出缺失项但未建立与误差的因果 |
| 消息传递 / GNN | **不推荐**：与 research_core 的"不以消息传递为核心机制"冲突；属模型类别替换而非机制；非 GNN 强基线已达 ~0.116 dev 水平 | `notes/research_core.md`；`results/strong_nongnn_predictor_v1/` |
| 集成 / 多种子平均 | **不作为主张**（历史冻结规则） | recipe 轮与各轮 gate |
| 标签加权 / 目标变换 / 尾部重采样 | **禁止** | 历史 protocol 禁令 |
| 配方 / 调度再搜索 | **关闭** | R3 为选择条件化候选；不追加搜索 |
| 监督期数据增强 / mixup 类 | **不推荐**：无支持证据，属方法开发而非已证据充分的机制；且与"不新增不可解释通路"的核心冲突 | 无正面证据 |

**判定**：在标准 ZINC-12k 下，**没有**同时满足
(证据充分) ∧ (与已有方法有明确区别) ∧ (真正改变可用预测信息) ∧ (未被关闭) 的候选机制。

## 5. 修订决定

### 5.1 决定

> **`NO_JUSTIFIED_NEW_EXPERIMENT`** —— 在标准 ZINC-12k 协议（官方 train 10k 监督 + 官方 train 10k
> 结构 SSL，外部结构不进入训练）下，本轮不推荐任何新的模型机制实验，也不授权任何 GPU 训练。

具体后果：

1. 不执行 H-COVER 50k / 220k 的 SSL 与 fine-tune；`EXPERIMENT_PLAN.md` 中对应设计**保留为备选**（§6）。
2. 不新增任何结构/读出/汇总/SSL/正则化模块；不重开已关闭族（§4）。
3. 现有冻结系统（R3 / P3）维持为当前主协议下的冻结系统；
   exposed-test `0.069822` 只作历史报告数字，不得用于新选择。
4. `notes/research_core.md`、`STATE.yaml`、历史结果文件均不改动。

### 5.2 未决定的事项（明确记录，避免误读）

* 独立确认类工作（新内部 grouped split 上复现 SSL/R3、或第二分子端点的方向一致性检验）
  是**有效性审计**，不是新机制；需研究者单独授权与预注册，本轮不自动执行。
* 是否把 H-COVER 作为**单独协议**（额外无标签数据）正式立项，见 §6。
* `research_core.md` 的条款修订建议见 §7，均需研究者确认。

### 5.3 重新开启决策的条件（预声明）

任一条件出现时，可重新评估"是否存在值得实验的新机制"：

1. 在**未暴露**的 split/端点上发现系统性、标签相关的表示失败（例如近邻对错分且不能由标签噪声解释），
   并给出能修复它的、区别于已关闭族与标准池化做法的机制设计；
2. 研究者明确授权把"额外无标签数据"作为独立协议立项（H-COVER 或别的数据侧假设），
   且同意其数字与主协议分开报告；
3. 出现新的评估端点/数据条件，使当前 10k 标签的局限可以被合法绕过（如新任务、新性质），
   且已有机制假设能给出先验的行为预测。
