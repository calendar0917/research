# BJOC Junction 充分性审计：给导师的汇报

协议 `cscl-bjoc-junction-sufficiency-audit-v1` · split D · seed 0 · 2026-10-15 讨论用

## 1. 研究问题

模型真正需要的是 **Junction 的局部内容**，还是 **真实的结构组织（哪个 Junction 属于哪条键）**？
我们只改"Junction 信息怎么进入下游"，不新增任何模块，拆成三档：
不加学习式 Junction 内容（A0）、只加全图 Junction 一阶/二阶矩（A1）、再按每条键的
Junction 个数缩放（A2，历史 Null 基线）。问题 B 单独审计：Null 在数学上、
在合成反例上、在真实分子上分别丢掉了什么。

## 2. 现有架构（一句话）

Atom → Bond → Junction → **Null 全图矩** → Reader。Junction 是"中心原子 + 两个邻居原子 +
两条物理键"的三原子两键组合（不是 3D 键角）。Null 把全图所有 Junction 编码压成
一阶矩 μ_G、二阶矩 ν_G，再乘上"这条键被几个 Junction 碰到"的计数 n_e 后广播给每条键；
**它保留全图 Junction 内容统计，但不保留"哪个 Junction 属于哪条键"的完整归属**。
Reader 输入 321 维 = Σc_b(96) + Σa_i(96) + Σa_i²(96) + 全图统计 g_G(33)。

## 3. A 的最重要三个数字

Monitor（split-D，1000 分子，历史暴露的开发数据；训练均为完整 360 epochs / 22,680 updates，
共享同一 scratch 初始化、同一 Fit-only SSL、同一 batch 顺序）：

| | A0（无 Junction 内容） | A1（+全图矩） | A2（+每键计数缩放，历史 P3） |
|---|---|---|---|
| Monitor MAE | **0.1215** | **0.1062** | **0.1040** |
| RMSE | **0.327** | 0.517 | 0.493 |
| 普通分子 MAE（y>−3，n=929） | 0.1026 | 0.0825 | 0.0811 |
| 极端分子 MAE（y≤−3，n=71） | **0.369** | 0.417 | 0.403 |

配对逐分子 bootstrap（5,000 次）：Δ(A1−A0) = −0.0153，95% CI [−0.0286, +0.0034]；
Δ(A2−A1) = −0.0023，CI [−0.0070, +0.0022]；Δ(A2−A0) = −0.0176，CI [−0.0302, −0.0007]。
按预先冻结的门槛（点估计 ≤ −0.002 且 CI 上界 < 0），前两项都**未达标**：
`J_MOMENTS_NO_CLEAR_GAIN`、`COUNT_CONDITIONING_NO_CLEAR_GAIN`。要点：

- Junction 矩不是"整体平移"：普通分子明显更好（−0.020 / −0.021），极端分子和 RMSE 反而更差；
  改变的是误差分布，不是全部变好。差异不由单个分子驱动（最大单分子贡献 3.7%–4.7%）。
- 这是**功能消融，不是容量匹配**：A0 有 143,776 个参数从一开始就结构上不可用
  （有效可训 65%），A1/A2 为 99.96%；所以"Junction 内容无用"的结论不成立。
- 单 seed、历史暴露 split：只能当机制信号，不是增益证明。

## 4. B 的一个最清楚的反例

4 条键（P1,P2,Q1,Q2）、4 个 Junction（X1,X2 值 1；Y1,Y2 值 2），两种归属：

- 归属 A：P1 接触 {X1,X2}，P2 接触 {Y1,Y2}，Q1/Q2 各接触 {X1,Y1}；
- 归属 B：同样每键碰 2 个 Junction、Junction 多重集完全相同，只换配对。

Null 的每键 W 在 A、B 中都是 `[3,3,3,3]`；Organized 的每键 W 分别是 `[2,4,3,3]` 与 `[3,3,3,3]`。
**Null 在数学上无法区分这两种归属，Organized 可以。** 已扩展成 m=2…5 的族：
Null 的每键 W/V 差恒为 0，Organized 的差 ≥ 0.0586，只依赖归属的人造目标差 8–36，
只依赖 Junction 多重集的目标完全相同。

两点必须一起说清：

- 这是**编码后、条件性**的表示级盲性：固定"每条键的表示、每键 Junction 计数、
  全图 Junction 多重集"时成立；不等于任意重分配都能对应真实分子。
- 因为 Junction 编码器的输入包含它触及的两条键的 embedding，**配对信息有一部分在编码前
  就进入了 w**（在 38 对构造中 Null 图级摘要最多差 785）。所以准确说法是：
  Null 保留全图内容统计、丢掉残差归属，而不是"从输入开始完全看不见归属"。

真实分子审计（official train 10,000 的结构字段，标签盲）：找到 3 组精确结构统计碰撞，
**全部是同一种分子重复出现**（canonical SMILES 相同），跨分子精确碰撞 0 组
（`REAL_COLLISION_NOT_FOUND_WITHIN_BUDGET`）。最近的不同分子 reader 输入距离为
3.35 个 Fit 标准化单位，而普通不同分子对的 1st percentile 是 14.26、中位数 22.59 ——
说明表示确实会"压缩"不同结构，但本轮没找到精确碰撞；搜索上限：signature 近邻 200 对、
有限统计键，不能证明不存在。

## 5. 已经确定的事实

1. **算法性质**：Null 的归属盲性在"编码后固定 w 多重集与每键计数"的条件下成立，
   代码与两个独立构造都支持；`n_e` 是计数不是归属。
2. **样本观察**：本 seed/split 下 A2 比 A0 好（CI 不含 0，−0.0176）；A1−A0 的 CI 跨 0
   （−0.0153），A2−A1 在阈值边缘、CI 跨 0（−0.0023）；Junction 矩让普通分子变好、
   极端分子与 RMSE 变差。
3. **结构审计**：真实 10k 上只有同分子重复构成的精确碰撞；近邻压缩真实存在（3.35）。
4. 结构 SSL 的原子/键遮挡恢复与下游 Junction 机制是两个不同研究问题；本轮没有重跑
   Organized-vs-Null。较低的 MAE 也不自动意味着结构贡献可解释。

## 6. 仍然没有确定的问题

- A1−A0 的普通分子增益是否在第二个 seed 复现；RMSE/tail 变差是优化问题还是重尾目标本身。
- 3.35 那类近邻碰撞是否对应可测的性质误差。
- 如果把真实归属显式保留（Organized 路线），能否修复极端分子的变差；历史证据混合，
  本轮按纪律没有训练。
- A0 的 65% 有效容量在多大程度上解释了它与 A2 的差距。

## 7. 希望导师拍板的两个方向

1. **定位问题**：如果"全图 Junction 矩 ≈ 每键计数缩放"在未来 seed 复现，是否接受把当前模型
   重新定位为**学习式局部结构统计预测器**，把研究转向"哪些结构统计足够、如何更省"？
   还是先训练第二个 seed 把 Δ(A1−A0) 的 CI 压下来再判断？
2. **设计问题**：若要研究跨分子的结构贡献，是否值得把"可归属的结构单元与关系"
   作为新的模型设计约束（例如在键-Junction 二部图上做可归属的局部聚合），
   并把"Junction 矩让 tail/RMSE 变差"作为这项设计的动机？还是先做子群误差归因分析
   再决定？
