## §1 决策

> **决策 C —— 证据不足以改变研究合同。本阶段继续 y-only 合同；下一笔 GPU 购买的唯一推荐 = 严格匹配的"预算对照"实验（§3 草案 1）。
> 分量监督路线（B）不立即启用：其严格受控增益 +0.0050(valid y-cal)/+0.0075(test) 真实且 CI 不含 0，
> 但小于 quasi-matched 的训练预算点估计 +0.0148/+0.0185，且 B 的监督是目标衍生（D 类），
> 会污染后续"结构贡献"科学叙事。只有在预算对照显示小效应（≤0.003）时，B 才升级为更优选择（§3 草案 2）。**

### ≤300 字决策摘要

审计表明历史 C 的 test 0.081 由三项叠加：训练预算（7.2k→10k，含步数与全量 refit）quasi-matched 估计 +0.015/+0.018，最大；严格匹配的分量监督 +0.005/+0.0075（CI 不含 0）；环通道离散解码 +0.0035（test，valid 单行主导）。关键受控对照（同代码同超参 7.2k vs 10k）缺失，数据量因果不可严格归因；架构与监督也未在同一骨架隔离。标签溯源：c/k 由 y 反推，k 依赖历史原子序（5.2% 置换不稳定），s 非纯 SA（ε-MAE 0.0027）；部署链不读真值 c，但分量监督改变信息条件、绑定 ZINC 定义。故不转合同：先买预算对照再定 A/B。

## §3 预注册草案

### 草案 1（推荐，对应决策 C 的唯一缺失证据）：`zinc-full-y-budget-control-v1`

**单一问题**：在**同一代码路径、同一超参、同一评估**下，把 Full-Y 的训练集从 fit_inner 7,200 扩到官方 train 10,000，
official valid 的 raw y-MAE 改变多少？

* **固定源**：`code/run_prediction_feasibility_v2.py` 及其 import 的全部 ksvd 模块（逐字不变）；
  `prep_fit7200.npz`/`encoded_train.pt`；冻结协议常量（240 epochs、Adam 1e-3、wd 1e-5、clip 5、batch 128、
  H1_LAMBDA=33.95873017865987、408,651 参数、seed 0）。
* **两臂（唯一差异 = 训练行集合及其随附的步数/refit）**：
  * Arm `A7200`：fit_inner 7,200；所有可拟合对象（标准化器、K-SVD 字典、公共子空间）refit 于 7,200。
  * Arm `A10k`：全部 10,000；同上 refit 于 10,000。
  * **统一 soup 规则 = 末 5 轮（epoch 236–240）参数均值**；两臂都不使用 monitor/dev 做任何选择
    （这是与现有 F 结果的唯一规则差；F 用 monitor top-5，需一并报告 `A7200` 与 F 的差作为"soup 规则敏感性"检查，
    若 |A7200 − F| 超出配对 CI，先调查再解释预算效应）。
  * 两臂共享初始化 seed 与行打乱生成器规则（各自的 7,200/10,000 行集合内同规则）；校准 = 各自 fit-only 中位偏差。
* **主端点**：official **valid** raw y-MAE，两臂各读取一次、在冻结后。**副端点**：`A7200` 的内部 dev（`A10k` 无内部 held-out，
  这是"买全预算"的固有代价）；两臂 fit 曲线；按 k 分层的 valid 表。
* **预注册 sanity check（在解释主结果之前必须先过）**：
  * `A10k` 的 valid raw 应当复现历史 `Y@10k` 的 0.118156（均训练全 10k、均末 5 轮 soup）——用两臂逐行配对 bootstrap；
    若 CI 不覆盖该参考值，先查实现/预处路径差异，暂停预算解释。
  * `A7200` 的内部 dev 应落在现有 F 的 0.11641 附近（同代码、仅 soup 规则不同）；偏离超 CI 则先查 soup 规则敏感性。
* **预注册判读**（三区间，写入协议后才允许读 valid）：
  * `A7200 − A10k` ≤ −0.010：**预算主导** → 继续路线 A，下一笔买更大预算/更强 y-only 架构；B 降级。
  * −0.010 < 差 ≤ −0.003：**混合** → 执行草案 2（同样 10k 预算、同骨架），以两者的配对 CI 做 A/B 抉择。
  * 差 > −0.003（即预算效应微小）：**表示受限** → B 的 +0.005~0.0075 相对更优，向用户提交合同变更请求 + 草案 2。
  * 统计：两臂 valid 逐行配对 bootstrap（1,000 次、共享索引、seed 固定）报告 95% CI；单臂不出结论。
* **预算**：2 次 A100 训练（各 ≈22 min，13,680/18,960 步 @≈5.5 s/epoch）+ 本地 CPU 分析；≤1 GPU-h、单 seed、无搜索。
* **禁止**：读 official test；用 valid 做超参/epoch/soup 选择；追加 seed/臂；改 λ 或架构。
* **披露**：official valid 将被再次读取（`test_access_record.json` 记录的历史读取 + 本轨先前读取）——本实验是
  暴露仪器上的**内部对照**，不是独立确认；结果写入 notes 后不得再以 test 佐证。
* **备选（若用户拒绝再读 valid）**：全内部版 `A'` = fit_inner 7,200 减去新划出的 1,600 行 canonical-group holdout（训练 5,600）
  vs `B'` = 用同一 7,200 训练，共同仪器 = 该 1,600 holdout。代价：预算对比度缩小、检验力下降；
  只有在"A/B 抉择允许更弱的功效"时才可选。

### 草案 2（条件性，仅 B 路线被触发时实施）：`zinc-full-y-component-supervision-matched-v1`

**单一问题**：在**目标骨架（Full, 408,651）与全 10k 预算**上，把主损失从 `L1(y)` 换成 `L1(g)+0.5(L1(ell)+L1(s))`
并接同一可部署环通道后，**可部署 ŷ** 是否优于匹配的 raw-y 臂？

* **两臂（唯一差异 = 损失与目标空间）**：
  * Arm `Y-only`：`L1(y) + λ·label-free 重构`（现行合同）。
  * Arm `COMP-deploy`：`L1(g) + 0.5(L1(ell)+L1(s)) + λ·label-free 重构`；部署 `ŷ = ĝ + ĉ`，
    `ĉ` 来自**共享的冻结环通道**（prototype 精确 T25 表 + 离散级别解码；仅用 fit 行构建/训练）。
  * 共享：初始化状态、行序、全部超参、epochs、soup 规则、逐臂 fit-only 校准、评估代码；两臂参数量相同
    （reader 最后一层 N→1 拆为 N→2 等分权重，构造法与既有 M 实验相同）。
  * 分量标签用 **fit-only refit 常量**计算（不读 eval 行标签常量）。
* **主端点**：可部署 `ŷ` 的 valid cal（与 dev）配对比较；副端点：g-MAE、逐分量 MAE、k 分层表、`ĉ` 误差。
* **预注册门限**（对齐既有 M 门）：overall y-cal gain ≥ 0.003 且 CI 下界 > 0，且 G0 worsening ≤ 0.001；
  全过 → 合同变更候选；否则 B 在该骨架上关闭。
* **明确写进协议**：这是**任务感知监督（D 类）**实验；`ell/s/c/k` 的定义依赖 ZINC 标签生成公式；
  结论只能表述为"已知分解的监督价值"，不得表述为"结构表示更强"。official test 不读。
* **预算**：2 次 A100 训练（同草案 1 量级）+ CPU 环通道分析。
