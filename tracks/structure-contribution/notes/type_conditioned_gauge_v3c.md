## 0. 答案概要（对应任务书 12 问）

1. **是**——新旧模型唯一主要结构变化 = δ 输入从 `[z|c]`（424）变为 `[z|c|Emb(t)]`（440）；
   α 仍为每类型 1 标量；γ 输入/参数/宽度、全局 bank、bias、冻结编码器逐位不变（测试+哈希钉住）。
2. **是**——共享初始化逐位一致（哈希全等）；δ 第一层旧 424 列逐位复制、新 16 列零初始化；
   未训练预测一致：**CPU 逐位相等（diff=0.0）**，GPU 上 1.19e-7（float32 GEMM 形状差，已披露）。
3. **是**——类型通道可学习（零初始化下新列先获得梯度、一步后 embedding 梯度非零）且真实被使用：
   真实 ZINC 上 18 个高频类型的 δ–附着数响应斜率离散（std 0.252，范围 [−0.67, +0.41]），
   而合成真值的斜率是类型无关的 0.8——模型确实学到了类型特异的上下文响应。
4. **改善 0.02108**：dev MAE **0.15209** vs S-gauge 0.17317，配对差 **−0.02108**
   CI [−0.02966, −0.01310]（与 v3b 相对 v3 的改善 −0.02234 同量级）。
5. **与 O 的剩余差距 +0.01080** [+0.00367, +0.01757]（v3b 为 +0.03188——缩小约 2/3）。
6. **是**——canonicalization 严格无损：pred|Δ|≤1.9e-6、MAE 差 <1e-8、fit 逐类型 canonical δ 均值
   1.9e-7、类型内方差保持、γ/全局/bias 逐位不变、导出加和恒等 1.8e-6。
7. **是**——分半规范化稳定性未恶化：可靠类型（每半 ≥10 实例）151 个，mean|m_t^A−m_t^B|=0.0380
   （v3b 0.0402）、α 排序 Spearman 0.9963（v3b 0.9953）；539/690 个出现类型低于门槛，单独报告。
8. **有证据**——δ 类型内 std 0.236（v3b 0.2423，上下文变化保留）；且斜率离散度（第 3 条）表明
   类型条件通道承载了真实的上下文交互差异；合成任务上 canonical δ 恢复 0.9988。
9. **否**——γ 未重新吸收类型信号：canonical 方差占比 1.8%（v3b 2.6%），γ–unit 相关 −0.416
   （与 v3b −0.324 同向）；全局通道 0.5%+12.5%（v3b 0.6%+12.7%），未成为旁路。
10. **维持**——合成（同 v3b 真值生成器/数据/种子，同口径）：α 符号 0.906/Spearman 0.950
    （v3b 0.938/0.914），δ raw 0.702→canonical **0.9988**、混淆 0.677→**−0.013**，真交互
    +0.874/−0.702/+0.498（真值 +0.9/−0.7/+0.5），混淆对 −0.005≈0，未见对 |γ̂| 0.014 vs 可见 0.082。
11. **是，不可消除**——新增 13,200 参数（embedding 表 12,176 + 新权重列 1,024），本轮无同容量
    对照；即使机制检查全部通过，改善也不能全部归因于类型条件本身。
12. **预注册判据读数：情况 A**（dev 0.15209 ≤ 0.16 且机制检查通过）——类型条件化支持
    "显式类型条件可恢复结构化贡献模型表达能力"的候选机制假设。下一轮（不自动执行）可研究
    完整距离桶 pair 矩 × 类型条件贡献的统一设计；但按任务书边界，O−F=+0.025 的输入信息
    压缩仍是 F 差距的主体，本轮证据不推翻该方向。

预冻结判断带读数：**情况 A**。不追加实验、不搜索 embedding 宽度、不运行 seed 1。

## 2. 唯一新架构：TypeCondContribHead

`pred = bias + Σ_u[α(t_u) + δ(z_u, c_u, Emb(t_u))] + Σ_r γ_r + g_ctx + g_topo`

- `Emb = Embedding(761, 16)`（与 O 的类型通道同宽度约定）；**只有 δ 读取 Emb**（AST 测试钉住：
  `unit_terms` 之外无 `type_emb` 引用；forward 无融合 MLP）；
- α 仍为每类型 1 共享标量；γ/global/bias 与 v3b 逐位同构（参数哈希钉住）；
- 未知类型不单独建 embedding：fit-only 词表 746 known + UNK 桶 = 761 id，UNK 行是普通词表行
  （实测 dev 未见签名全部落入既有 UNK 桶 id）。

### 2.1 初始化纪律（控制初始化混杂；容量混杂不可消除、已披露）

1. seed 0 构建未训练 v3b `SBContribHead`；
2. seed 0 构建新头，所有形状未变参数**逐位复制**（哈希全等）；
3. δ 第一层旧 424 列逐位复制，新 16 列**零初始化**（冻结规则）；
4. `Emb ~ N(0, 0.1²)` 来自独立 `torch.Generator(seed=0)` 流（不消耗共享流，可复现验证）；
5. 从头训练（**禁止**加载已训练 v3b checkpoint）；
6. 未训练预测一致：CPU 逐位相等（pred diff **0.0**）；GPU 1.19e-7（GEMM 形状差，float32 舍入级）；
7. 通道可学习性实测：零初始化 ⇒ 第 0 步新权重列梯度非零、embedding 梯度为零；一步后
   新列非零、embedding 梯度非零、扰动 embedding 即改变 δ（测试钉住）。

参数量：118,168 → **131,368**（+13,200 = embedding 12,176 + 新列 1,024）。
**这既是类型条件通道，也是容量增加；无同容量对照——改善不能全部归因类型条件（§0 第 11 条）。**

## 3. 训练目标与 gauge（Phase C）

- 目标 = v3b 逐字：`L1(raw y) + 1.0·γ batch 均值惩罚`；无 δ 惩罚、无 embedding 正则、
  无 α 锚定、无蒸馏、Full-Y 预测从不作为输入或标签（AST 钉住）；
- 超参/调度/checkpoint 规则与 v3b 相同（Adam 1e-3 / wd 1e-5 / clip 5 / batch 128 / 240 epochs /
  shuffle generator 101 → **与 v3/v3b 完全相同的 batch 序列**；primary best-monitor 单检查点，
  secondary 预注册 top-5 monitor soup；无 early stopping、不用 dev 调参）；
- gauge 规范化**复用 `contribution_gauge.py` 原实现**（最小重构：`GaugedHead` 委托
  `head.unit_terms(batch)`，同一 wrapper 服务 v3b/v3c 头；`load_gauge` 增加 head_builder 参数）。
  类型条件化不改变 gauge 代数：m_t 仍是逐类型常数；语义边界（§5.3）：
  **canonical α 只能解释为 fit 分布下按规范化约定定义的类型平均基础贡献，不是与上下文无关的
  化学常数**（m_t \|均值\| 0.734、max 7.36；canonical α 值域 [−7.97, +1.83]）。

## 5. 解释审计（`analysis_s0.json: S_typecond_audit`）

## 8. 科研判断（预注册判据）

**情况 A 成立**：dev 0.15209 ≤ 0.16，且 (a) 严格加和恒等（独立 numpy 重建 1.8e-6）；
(b) canonicalization 预测无损；(c) α 分半稳定性未恶化（0.0380/0.9963 vs v3b 0.0402/0.9953）；
(d) 合成真值恢复未退化（canonical δ 0.9988）；(e) γ（1.8%）与全局（13%）未成为补偿旁路。

因此：**显式类型条件化与剩余 S–O 差距的缩小相容，且类型通道确实承载了类型特异的上下文
响应**（斜率离散度 + 合成恢复）。但按预注册解释边界：

- 容量混杂不可消除（+13,200 参数，无同容量对照）——改善不能全部归因类型条件本身；
  本轮是"表达缺口候选机制"的验证，不是严格的机制归因证明；
- 单 seed 0；bootstrap 为分子重采样区间，非跨 seed 稳定性；
- dev 已被多轮使用；所有数字是内部 dev 的探索性开发证据；
