# FOLLOWUP_DIAGNOSTIC — ZINC DCC 审计头重检与 H-C 条件增量

冻结基线：`b3a6f8e`。本轮只做 CPU 诊断；无 GPU、无新架构、无新统计族。
数据边界：只使用 **ProbeFit 1000 行**的标签；**AuditEval 标签未读取、未重打分**；official valid/test 从未加载。
旧 AuditEval 数字仅从冻结的 `analysis/b/s{0,1}/metrics.json` 复制，用于说明旧审计仪器的行为，不作为本轮证据。

## 0. 结论

- **预注册判定：`NO_REASON_TO_REOPEN_J_FAMILY`。** 修复后的低维 LAD/median OOF 没有发现稳定增益：
  `J_raw` 两个 seed 的条件增益均为负；`J_latent` 与 control/null 不可区分。
- **有效范围必须写清楚：** positive control 在 oracle 增益 `0.005` 上 6/6 检出；在 `0.003` 上只有 5/6（seed 1 为 2/3，且幅度被压缩）。因此：
  - 对 **≥0.005** 的增益，本轮阴性结果是有效的；
  - **0.003 没有被完全排除**；若严格要求 0.003 也必须稳定检出，则 0.003 这一端应标为 `AUDIT_UNDERPOWERED_OR_INVALID`，不能据此宣称“0.003 不存在”。
- **旧 H-C 阴性中审计头的责任：**
  - 旧头把 MAE 从 raw 的 0.075 推到 0.267/0.320（AuditEval），这个 **0.19–0.25 的巨大退化几乎全部是头/校准失败**，不是 J 的信息结论。
  - 但旧结论“没有稳定 J 增益”**不是**头造成的：修复后仍无增益；旧的正向 `Gain_J ≈ +0.0034` 未复现（修复后 `J_raw ≈ −0.00069`，`J_latent ≈ −0.00001`）。
- **是否值得再确认：否。** 没有提出 confirmation design；不应再使用 AuditEval 标签做确认，也不应因此启动 GPU。
- **J_raw/J_latent 这条线：作为预测候选停止。** 不是宣称“联合结构关系永远无信息”，而是：在当前表示、当前数据、当前 readout 与当前效应量下，没有值得再投入的证据。

一句话：**旧审计头确实把 H-C 测坏了；修好之后 H-C 仍然是否定的，只是现在这个否定只对 ≳0.005 的效应有把握。**

### 1.3 两个极端分子解释了几乎全部残差平方和

ProbeFit 残差最大的两行：

### 1.5 Task 1 的答案

**问：以前的 H-C 阴性，有多少是审计头造成的？**

分两层：

1. **“头比 raw 差 0.19–0.25 MAE”这一现象：几乎 100% 是审计头/校准失败。** 证据是 top2 的 97% SSE、alpha 边界、MSE/MAE 错配、Huber 不收敛、条件数 1e17–1e39。
2. **“没有稳定 J 增益”这一结论：不是头造成的。** 修复后的低维 OOF 仍无增益（§2）；旧的正向 `Gain_J ≈ +0.0034` 没有复现。旧的正增益是坏头之间的差，不是 J 相对 raw 的增益。

所以旧 H-C 应改成更准确的表述：**旧测量无效；旧结论（无稳定增益）在修复后仍然成立。**

## 2. 最小稳健条件增量检验（Task 2）

### 2.1 设计

- `J_perp = J − J_hat(z)`；`J_hat` 是 B3 在 **Fit8k** 上训练的无标签重构器，ProbeFit 标签不参与构造。
- 两个统计块分开：`J_raw` 21 个有效维（11 个近常数维按冻结配置排除）；`J_latent` 4 维。
- 三个比较器：
  1. **raw**：原始 DCC-L 预测；
  2. **C（control）**：只用现有表示的低维信息 `z[:,288:321]`（global33）做稳健校准；
  3. **CJ**：同一个低维校准 + `J_perp`。
- 估计器：`QuantileRegressor(quantile=0.5, solver='highs')`（LAD/median），嵌套 5 折选择 alpha，训练折内标准化，训练折内 1%–99% clip；外层 5 折 OOF。
- 主 MAE 包含 **全部 1000 行**，不删极端样本。
- null：在 ProbeFit 内整体置换 `J_perp` 行（保持边际），5 次。
- positive control：把随机单位方向（对 `[1, global33]` 正交化）加到经验残差上，用 t3 噪声（scale 0.05）和 beta 二分，使 oracle MAE 增益为 0.003/0.005；每个 seed、每个 block、每个目标 3 次重复。
- 定义：`Gain_CJ_control = MAE(C) − MAE(CJ)`；`Gain_CJ_raw = MAE(raw) − MAE(CJ)`。正值表示 J 有用。

### 2.8 判定逻辑

按冻结配置：

- positive control 在最大目标 0.005 上检出率 1.0 ≥ 0.8 → 仪器不是全局失效；
- 真实数据没有任何 seed/block 满足“`Gain_CJ_control` 与 `Gain_CJ_raw` 均为正、超过 null 95%、且 ≥0.003”；
- 因此自动判定为 **`NO_REASON_TO_REOPEN_J_FAMILY`**。

边界声明：若把 0.003 也作为必须稳定的目标，则应把 0.003 这一端标为 `AUDIT_UNDERPOWERED_OR_INVALID`；这不改变“没有值得现在再确认的正增益”的结论。

## 3. 对三个问题的直接回答

### Q1. 以前的 H-C 阴性，有多少是审计头造成的？

- **“头比 raw 差 0.19–0.25 MAE”这部分：几乎全部是审计头造成的。** 直接证据：top2 占 97% SSE、alpha 在边界、seed 1 的 MSE/MAE 选到相反端点、Huber 300/10000 都不收敛、条件数 1e17–1e39。旧头不是 J 的测量仪器。
- **“没有稳定 J 增益”这部分：不是审计头造成的。** 修复后的低维 LAD OOF 仍然没有增益；`J_raw` 两个 seed 都为负，`J_latent` 与 null 不可区分。
- 旧的正向 `Gain_J`（+0.0034 左右）是两个坏头之间的差，未复现；因此不能把它当作“J 有微小信号”的证据。

### Q2. 当前统计族里有没有值得再确认的预测信号？

**没有。**

- `J_raw`：seed 0 `−0.001126`（CI 完全为负），seed 1 `−0.000261`（CI 跨 0）；两个 seed 都没有正增益。
- `J_latent`：`+0.000002` / `−0.000022`，CI 都跨 0，且低于 null 95%。
- 没有分层在两个 seed 上同时为正且 CI 排除 0。
- 0.005 的 positive control 为 6/6；因此“没有 ≥0.005 的增益”是有效的。0.003 只被部分排除，但观察到的点估计接近 0 或为负，没有任何“接近 0.003 的正信号”值得再确认。

### Q3. 是否应该结束 J_raw/J_latent 这条线？

**作为当前表示/数据/readout 下的预测候选，应该结束。**

- 不再为这一统计族启动 confirmation 训练；不再使用 AuditEval 标签做第二次确认；不再做新的架构搜索。
- 旧报告中的 `NO_JUSTIFIED_NEW_MODEL` 仍然成立，而且现在更清楚：问题主要不是“没找到正确聚合”，而是这批联合统计量在当前标签/数据上没有可测的条件增量；同时旧审计头本身也不可靠。
- 如果未来仍要检验“0.003 是否存在”，那需要的是 **新的独立标签集/更大样本、预先注册的效应量与功效设计**，而不是重开这条线或再读一次 AuditEval。就本轮证据而言，没有理由投入 GPU。
