# ERRATA — ISRD-v0 实现错误与影响范围

本文件记录 `interpretable_structural_rule_discovery_v0`（冻结 commit `6cddf702`）中
已确认的实现错误、修复方式与**实际影响范围**。v0 的历史记录只读保留，不覆盖；
本轮 v1 的受影响实验在 `analysis/metrics.csv` 中标记
`SUPERSEDED_BY_RULE_MAPPING_FIX`。

---

## E1 — 按模型区分的结构列映射错误（核心错误）

**位置**：`interpretable_structural_rule_discovery_v0/code/isrd_common.py`
（`OFFSET = {"C": H_WIDTH, "F": H_WIDTH + N_C}`）与
`code/isrd_rules.py`（`split_nodes` / `path_conditions` 中的
`gran = "C" if gidx < H_WIDTH + N_C else "F"`）。

**错误**：v0 用统一的 `H + C + F` 布局解释两个单粒度 booster。

**事实**（由 booster 自身的 `num_features` 与 `save_config()` 核验）：

| arm | 真实输入 | 宽度 | 结构列 |
|---|---|---:|---|
| X-C | H + C | 3012 = 2258 + 754 | 全局 `2258+i` ↔ `C[i]` |
| X-F | H + F | 5910 = 2258 + 3652 | 全局 `2258+i` ↔ `F[i]` |

**实际后果**：

* X-F 在全局列 `[2258, 3012)` 的 **1 420 个结构分裂节点（174 个不同列）** 被读成 `C[0..753]`（真值 `F[0..753]`）；
* X-F 在全局列 `[3012, 5910)` 的 **1 970 个节点（459 个不同列）** 被读成 `F[i-754]`，整体错位 754 列；
* X-C 的映射本身正确，因此 v0 的候选池混合了正确（X-C→C）与错误（X-F→C/F）来源。

**可核验证据**：

* X-F 共 3 390 个结构分裂节点，v0 全部按错误布局解码；X-C 的 2 852 个节点正确。
* v0 产生了 **38 条 C–F 真实联合规则**。两个单粒度 booster 不可能产生跨粒度路径，
  因此这 38 条本身就是映射错误的直接证据（v1 中为 0）。
* v0 R128 的规则粒度构成 95 C / 33 F；修正后 61 C / 67 F。
* v0 的 “COARSE 419” 规则混合了来自 X-C 的 `C[419]`（芳香碳—硫）与来自 X-F 的
  `F[419]`（完全不同的结构），因此 v0 关于该家族的“规则使用情况”陈述不可用。
* v0 声称“四个 C–S FULL 子型没有一个进入 512 候选池”。修正后 `F[2078]` 是
  **来源树最多的单规则之一**（26 棵来源树），并直接进入 R64/R128（S002/S003）。
  该结论被推翻。
* 预测层面：v0 R128 = Valid 0.7702 / Test 0.7637；v1 R128 = 0.8046 / 0.7873
  （Δ = +0.0345 / +0.0236，Test 区间跨零）。错误**低估**了 128 条规则的性能。

**影响范围**：v0 的 `R16/R64/R128`、`B2-L64/B2-U64`、`B2-U+S/P/N`、`R64+P`、
所有知识卡片、Phase D 的规则使用陈述。
**未影响**：`R0`（仅分子大小）、B2 系数与预测重放、历史 `X-C/X-F/X-CF/B0/B2/B3`
指标与预测（直接从冻结 booster/系数读取，不经过该映射）。

**修复**：`isrd1_common.decode_feature(arm, feature_idx)`，带列范围检查；
`split_nodes` / `path_conditions` 全部经由该函数；另加直接列值核验（见
`analysis/phaseA_mapping.json`：映射后结构列值 vs booster 原始输入列值，
max|Δ| = 0；30 棵树 × 2 000 行叶节点重放零错位）。

## E2 — 真实路径条件提取丢失阈值与分支方向

**位置**：v0 `isrd_rules.path_conditions()`。

**错误**：只保存路径上的全局特征编号；`mine_pairs()` 再用
`(gran, column, threshold)` 反查唯一阈值。实际节点阈值与**经过的分支方向**没有保存，
所有候选统一写成 `x >= t`。若真实路径在某个节点走 `yes`（`x < t`），v0 仍以
`x >= t` 表示该条件；同一结构在路径上出现多个阈值时也无法区分来源。

**后果**：v0 的 `PROJECTED_PAIR` 并不忠实于真实路径；这是“树路径联合规则无价值”
这一结论的**有效性前提被破坏**，而不是对该结论的支持。

**修复**：v1 逐节点递归，条件身份为
`(granularity, column, float32 threshold, direction)`，并保存
arm / tree / node / missing 方向。`analysis/phaseA_mapping.json` 的 `path_replay`
用真实设计逐叶重放（yes ⇒ `x<t`，no ⇒ `x>=t`），30 棵树各 2 000 行零错位；
`tests/test_isrd1.py::test_real_path_conditions_reproduce_leaf_assignment` 另行独立验证
每个叶节点的条件集合恰好划分样本。

## E3 — 联合规则主效应资格与随机匹配不严格

**位置**：v0 `run_phaseBC.pair_eligible()` 与 `run_phaseA_rules.main()` 的随机匹配。

**错误**：

1. 资格只检查 `(granularity, column)` 是否在 U64 中，未检查阈值与方向是否一致；
   一个“同名结构、不同阈值”的条件也被当作主效应已存在。
2. 随机匹配使用加权 cost，无显式容差；实际覆盖 82.4%，边际激活频率最大差 **0.48**，
   联合频率最大差 0.0968。因此 `P−N` 不是严格对照。

**修复**：v1 用精确条件身份（允许精确补集，阈值必须一致）判断资格；
随机池为 U64 条件的精确闭包（64 + 64 补集）；边际频率容差 0.05、联合频率容差 0.03、
四格支持同规则、一对一无放回。实际匹配 37/39，最大 |Δfreq| ≤ 0.05，
|Δjoint| ≤ 0.03（见 `analysis/phaseBC.json` → `phaseC.joint.match`）。

## E4 — 知识卡片与数值语义错误

| v0 陈述 | 实际 | v1 处理 |
|---|---|---|
| “COARSE 157 是 triangle” | registry：`size-3`，3 节点 / **2 键**，`C-C-O` 芳香三节点，无环 | 卡片改为“带一条芳环边与一条 C–O 芳香边的三节点路径”，并给出 `n_nodes/n_bonds` |
| “0.142857 ≈ 1/sqrt(7)” | `0.142857… = 1/7 = 1/sqrt(49)`；`1/sqrt(7) = 0.377964` | v1 卡片一律写作 `t = 1/sqrt(k)` 之前先验证 `t²·k = 1`；不手工命名 |
| 若干“原始计数”描述 | 由 `scaled_count * sqrt(n_atoms)` 还原时未逐分子核验 | v1 在全部 3 969 616 个非零单元上核验 `count == round(x·sqrt(n_atoms))`，并优先取实例缓存的整数计数 |
| 首页与卡片的规则系数符号可能不一致 | 手工复制 | v1 的报告与卡片由 `write_report.py` 从同一份 `phaseBC.json` 生成 |

另外，v0 多处把“在观察数据上成立”的阈值读法写成等价关系。v1 只在 Train 上核验
`activation == (raw_count >= k)`（512 条中 26 条成立），并明确标注为
**经验等价**，不宣称对所有可能分子逻辑等价。
