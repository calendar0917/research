## 0. 一页结论（先回答六个问题）

**1. 上一轮 `XGB_STRUCT` 的增益最可能来自什么？**
最可能是「普通结构计数信息 + 高容量非线性读出」，**不是**某一类精确连通子图的特殊身份。
把 4406 个真实子图列换成 2048 维折叠 Morgan **计数**（`X-MC`，Test AUC 0.7800 vs `X0` 0.7624，
Δ +0.0176，CI [+0.0030, +0.0334]）就恢复了 `X-CF` Test 增益的约 40%；换成二值化的
presence 版本（`X-PRES`，Test 0.7930，Δ +0.0306）与 `X-CF`（0.8070）在 AUC 上**不可分辨**
（`X-CF − X-PRES` Test Δ +0.0139，CI [−0.0020, +0.0303]）。即：**重复出现次数几乎测不到额外价值，
"结构出现过"这一步就已经拿到了大部分增益**。
**被削弱的解释**：「真实父子层级/支持度」在上一轮已被否证，这一轮进一步削弱「精确连通子图身份」和
「重复计数」两条。**仍然不能区分的**：属性精细程度（`COARSE` vs `FULL` 与 `WL` 差异在 CI 内）、
候选分裂空间大小（各臂 colsample 比例相同但列数不同）。

**2. 显式连通子图相对 Morgan 与 WL 是否提供了额外价值？**
**弱证据、方向一致但不稳健。** Test 上 `X-CF` 优于未折叠 Morgan 计数（`X-CF − X-MU` +0.0212，
CI [+0.0032, +0.0413]，不跨 0）与同属性 rooted WL（`X-CF − X-WL` +0.0182，CI [−0.0002, +0.0380]，
边界）；Valid 上两者分别为 +0.0089 和 +0.0024，均跨 0。按协议规则只能写成
「Test 上有意义、Valid 上不可分辨」，**不是**一致优势，因此保留真实连通子图作为后续候选，
但可以说：现有局部环境表示（尤其是带属性的 WL）已经拿到其中大部分可测收益。

**3. 粗细结构是否互补？数量信息是否重要？**
**不互补的证据多于互补的证据。** `X-CF − X-C`（FULL 在 COARSE 之上的条件增量）Valid −0.0116、
Test +0.0143 → `SPLIT_CONFLICT`；`X-CF − X-F`（COARSE 在 FULL 之上）Valid +0.0003 / Test +0.0067，
两者 CI 均跨 0。也就是说：**单独给 COARSE 已经能拿到 Valid 上最好的 AUC（0.8445），加上 FULL 不增加
Valid 排序能力**；但 AP 上 FULL 明显更强（`X-CF` Valid AP 0.4331 vs `X-C` 0.3937），说明 FULL 改善的是
正例附近的排序而非整体 AUC。数量信息：`X-PRES`（去掉重复次数）Valid AUC 掉到 0.8212（−0.0155 vs X0，
CI [−0.0361, +0.0073] 跨 0），是**降幅最大的**结构臂，但它的 AP 也最低（0.3758）；`X-CF − X-PRES` 的 AP 差 Valid
+0.0573（CI [+0.0251, +0.0893]，不跨 0）。所以「重复次数」对 AP 有可测价值、对 AUC 没有。

**4. 相同输入能否让 MLP 获得相似的结构增量？**
**不能，但差距不是"完全学不到"，而是"弱一个量级且不可分辨"。** `N-CF − N0`：Valid +0.0034
（CI 跨 0）/ Test +0.0131（CI 跨 0）；对应 `X-CF − X0`：Valid −0.0038 / Test +0.0445。
`N-WL − N0`：Valid +0.0029 / Test −0.0028（`SPLIT_CONFLICT`）。`N-CF − N-WL` Test +0.0159，
AP +0.0692（CI [+0.0142, +0.1147]）——真实子图块**相对 WL 块**在 MLP 上仍略有价值。
同时 `N-WL` 把 Train AUC 推到 0.9956（N0 0.9847、N-CF 0.9851）而 Valid/Test 不升反降，是明确的
**Train 拟合膨胀而不迁移**。两种读出改善的分子几乎不重叠：逐分子 Δ 的 Spearman 只有 0.10
（Valid）/ 0.10（Test），sign 一致率 0.53，改善前 10% 集合的 Jaccard 0.12。

**5. ZINC 上是否出现相同现象？**
**部分相同、读出格局相反。** `ZX1 − ZX0`：Valid MAE 差 0.0000（CI [−0.0120, +0.0113] 跨 0）、
Test +0.0167（CI [+0.0040, +0.0274]，不跨 0）——与 MolHIV 的「Valid 不动、Test 改善」同型；
`ZN1 − ZN0`：Valid +0.0164（CI [+0.0002, +0.0357]）、Test +0.0249（CI [+0.0092, +0.0431]）——
MLP 在**两个划分上都**拿到增量。所以「显式结构块有增量」不是 MolHIV 分类任务的特例；但**哪个读出
能利用它依赖任务**：MolHIV 上是 XGBoost，ZINC 上是 MLP。注意 ZINC 上 MLP 的基础水平本身远好于
XGB（0.284 vs 0.469），所以「读出差异」与「基础能力差异」在本轮**不可分离**。

**6. 哪些具体结构规律值得进一步学习，哪些设想暂时没有证据？**
值得继续跟进的（都有实测 gain 支撑）：芳香碳–芳香碳/芳香碳–杂原子的 2 原子边、
尺寸 4 的"芳香环+取代基"片段、以及 cycle-6 芳香环骨架（占 `X-F` 结构 gain 的 48.4% / 25.9% / 1.4% 分布中，
size-4 与 size-3 是大头，但 cycle-6 在按列使用时 11 个列就拿到 1.4% 的 gain）。
**暂时没有证据的设想**：重复计数作为独立信号（AUC 无增量）、父子层级/支持度（上一轮已否证，
本轮未再测）、以及"更复杂的子图发现能带来新收益"——在本轮预算下，**没有任何一条对照能把
`X-CF` 与「带属性的局部环境 + 更好的读出」区分开**。因此本轮结束时仍无法定位一个可独立复现的
"精确连通子图"机制；这是一个**尚未解决的问题**，不应用下一轮模型设计去掩盖。

## 2. Phase 0.1 — 化学属性解码修正（ERRATA，仅展示层）

修正内容与证据见 [ERRATA.md](ERRATA.md)。要点：

* 原子类别索引 5 = 原子序数 6 = **C**；MSDS-v0 显示为 **B**，并且把电荷类别索引 5（= 0）显示成 **+5**
  —— 真实字符串是 `B+5`。键类型同样整体错位（`SINGLE` 显示为 `DOUBLE`，`AROMATIC` 显示为 `TRIPLE`）。
* 影响范围（COARSE 词表）：754/754 列至少一个节点标签错误；FULL 3652 列同样全数受影响。
* **进入模型输入路径？没有。** 三重独立证据：(a) 冻结产物中不存在字符串数组，`full_keys`/`coarse_keys`
  只解出整数元组；(b) 用原始整数索引重新推导冻结词表，选择与父映射完全一致；(c) 重建的 C/F 设计矩阵与
  冻结 `design_CF.npz` 最大绝对差 **0**，`phaseA_instances` / `design_CF` / `vocab` / 历史特征 /
  历史预测的 sha256 全部与各自记录值相同。(d) 源码扫描：3 个展示函数共 7 个调用点，全部位于只写
  CSV/JSON/图标题的函数体内。
* RDKit 独立核对（全部 41 127 分子、1 048 955 原子、1 129 451 键）：在「存储索引 = OGB 自身编码器对
  SMILES 重解析的结果」这一条件下，**9 个原子字段与 3 个键字段全部 0 不一致**。剩余 372 原子 / 839 键的
  索引差异来自数据集级 **SMILES ↔ 原始图漂移**（148 个分子、7 个 SMILES 无法解析），与本解码器无关。
* 修正后的 registry 在 `analysis/registry_v1/`（COARSE/FULL 各一份 + `structure_types_v1.csv`）。

XGBoost」。不是"容量不足导致完全学不到"：`N-CF − N0` 在 Valid 与 Test 上同号；也不是"两者都能区分

**并没有**在同一批分子上获得结构收益。

边界：`N-WL`/`N-CF` 比 `N0` 多 563 968 / 563 968 个首层参数，容量未完全匹配；固定统计向量 MLP 只是
图级读出，**不是**端到端子图表示学习。

## 10. 尚未解决的问题（明确留在本轮之外）

1. **为什么 Test 系统性改善而 Valid 不动**：六个新臂几乎全部如此，这不是某一个特征块的偶然。
   单 seed 下无法区分「Valid 与 Test 的 scaffold 分布差异」「Test 更接近新骨架而结构列在此更有用」
   与「Valid 恰好是噪声上的一次抽样」。
2. **哪一种结构语义真正带来增量**：本轮已把候选压缩到「高频 size-3/size-4 芳香片段 + 芳香环」，
   但没有任何对照能把"精确连通子图"与"带属性局部环境 + 同等读出"区分开。
3. **MLP 为什么只拿到约 30% 的增量**：不是简单容量问题（Train AUC 已接近 1），也不是完全没有
   （同号）；可能与零初始化支路在 best-Valid epoch（3–5）之前几乎没被训练有关——本轮配方冻结，
   不做这种事后调参。
4. **ZINC 上读出与基础能力的混淆**：MLP 既是最强基模型又是有增量的模型，无法在本轮区分
   "读出适配"与"基础能力更强"。
