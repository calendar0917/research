## 1. 结论

**最终建议：`PRIORITIZE_RESPONSE_ALIGNED_OBJECTIVE`（优先研究"响应对齐的训练目标"）**
——并附带一个明确的未决问题：该目标当前在 official Train 规模上优化不稳定，这是下一阶段
必须先解决的问题，而不是再去换网络或再加潜势。

一句话证据链：

1. 结构响应算子本身**确实有信号**：固定 `H_IND` 把 eta 从 STAR 换成 FULL，Valid RMSE 从
   `0.797489` 降到 `0.707858`（best 增益 `0.08963 = 0.074 σ_A`，配对分子 bootstrap CI
   `[0.0272, 0.1415]`）。这是本轮最强的单一结构算子对照。
2. 但这条路线**明显不具竞争力**：最好的联合树模型（`H_IND + ETA_FULL`）是强参照
   `B_ref = 0.62874` 的 **1.126 倍**，`H_FULL + ETA_FULL` 是 **1.170 倍**，都落在
   协议预设的 ">1.10 明显差距" 档。全图联合根响应（ROOT）分支因此**未触发**。
3. 整棵树 H 与 eta **互相替代而非叠加**：单独全图 H 有 `0.0313` 的增益，但在 eta 已开的
   条件下再叠加 `H_FULL` 反而**变差** `0.0279`（MSE 中中差 `−0.0891`）。"根响应 + 全图
   平均势"不是可加的两种信息。
4. 在严格真实编辑挑战上（276 对 Dev-Dev 精确结构替换），**训练目标是唯一在所有三个模型
   家族里都稳定改善响应预测的因素**：component-equal edit_MAE 相对 BASE 下降
   `0.0407 / 0.0421 / 0.0421`（RESP_PRODUCT / RESP_FUSION_MLP / GINE_G0，约 −10%），
   相对 ENDPOINT 下降 `0.0476 / 0.0383 / 0.0437`。
5. 同样端点暴露下，**结构算子没有带来 GINE 之外的额外编辑收益**：
   `CE(GINE_D) − CE(RESP_PRODUCT_D) = −0.0021`，配对分量 bootstrap CI
   `[−0.0496, +0.0454]` 跨 0，即两者在统计上无法区分（GINE 甚至略好）。收益来自目标，
   不来自"哪个结构模型"。
6. 代价是真实的、但不大：DELTA 的 Dev 分子 RMSE 是 BASE 的 `1.010 / 1.020 / 1.043` 倍；
   接回 official Lipo 后（GINE 行）是 `1.033` 倍 BASE，且仍在参照的 `≤1.05 接近` 档。

因此：**不要**把下一步投在"更精确的全图根响应"（R 分支已按规则跳过），也**不要**把
"片段条件响应"当成已被证明的优势（它在编辑响应上不比 GINE 强）。要投的是把
`L = L0 + λ·½(e_B − e_A)²` 这类响应对齐目标做成**稳定可训练**的东西。

三点必须一起读：

1. **BASE 已经打到参照水平**（`0.996×B_ref`），而它在 D0 上也是三者里整分子最好的
   （`0.5420` vs `0.5478` vs `0.5679`）。也就是说"参照水平"本身不再能当作结构响应路线
   必要性的证据：一个诚实的 GINE 基线就够到它。
2. DELTA 在 official 切分上的**分子代价是 1.033×**（仍在 `≤1.05 接近` 档），MAE 反而最好。
3. DELTA 这个臂在 official 规模上**优化不稳定**：360 个 epoch 的 Valid RMSE 在
   `0.649–6.22` 之间跑（最后 100 个 epoch 仍在 `0.649–2.17` 之间来回，只有 4 个 epoch
   低于 0.70），末轮 `0.861`；相比之下 BASE 最后 100 个 epoch 稳定在 `0.638–0.673`。
   因此 DELTA 的 `best` 是"冻结规则从噪声轨迹里挑出的最小值"。协议冻结的辅助前向在
   `eval()` 模式下跑（保证不改 BN buffer 与训练 RNG），于是 pair 项与 base 项看到不同的
   归一化统计；这一支在该设计下是脆弱的。**这是下一阶段先要解决的问题**，
   不能把 `0.649` 当成一个稳定水平来引用，也不能反过来用它宣布目标无效。

## 8. 工程核验与失效记录

三层核验全部通过（`analysis/checks.json` 26 项、`analysis/checks_d0.json` 5 项、
`analysis/checks_analysis.json` 11 项，`all_required_pass = true`）：

* 历史重放：FGCR `H_FULL/ETA_FULL` 在 Valid420 上 `0.7128936`（历史 `0.7128937193209034`，
  差 `≤1e-4`）；float64 brute force 最大误差 `1.8e-15`；精确保真（orig vs variant `0.0`）。
* 置换/键反向/顺序不变 `7.6e-06`；零 coupling 响应为 0；单边/互不相交单边 FULL=local；
  链/环增量非零；belief 调用次数 `A_IS=0`、其余每 batch 恰 1 次。
* 目标恒等式 `L_DELTA − L_ENDPOINT = −λ/(1+λ)·E[e_A e_B]`（`2.8e-17`）；端点交换不变。
* 辅助路径不改 BN buffer / 训练 RNG / 基础梯度；恢复 train 状态正确；BASE 步对是否执行
  辅助前向逐位不敏感（`base_gradient_insensitive_to_aux_path`）。
* pair schedule 端点严格 Fit-only；E/D 共用同一冻结 schedule（sha256 `0718ed22…015e`）。
* RESP 零初始化 `w` 确实离开 0（一步后 `|w|∞ = 3.3e-3`）。
* checkpoint 重载精确复现；九个 best/final 的 SHA-256 在打开编辑评价**之前**冻结
  （`checkpoints/manifest.json`，`run_analysis.py` 会校验并在不匹配时拒绝运行）。
* 编辑 delta 的独立重算（不经过分析脚本的封装）与写入 npz 的值**逐位相同**
  （`max_abs_delta_diff = 0.0`），component-equal MAE 从 delta 重算亦完全一致。

**本轮真实发生并修复的两个失效**（完整清单见 `analysis/deviations.json`）：

1. **RESP 预测取错分子**（01:12 发现）。`sr_resp.predict_std` 把"要评价的行在批内的位置"
   当成"分子在 split 内的下标"，于是每次 eval 都在给 split 的前 n 个分子打分。
   症状：训练损失正常下降（`base_loss` 路径没错），但 Dev RMSE 从 epoch 1 的 1.22 一路
   *升* 到 1.68，且 `predict(fit)` 的 RMSE 是 1.61 而不是 0.24 —— 自洽性检查暴露了它。
   处置：修复为 `rows[idx]`；**两个已经在跑的 RESP 行（BASE 已完成、ENDPOINT 进行中）
   整体作废**，输出归档到 `results/B_invalidated/`，三臂用同一 commit 从 reset 重跑
   （`sr-b-prod1`、`sr-b-fus1`）。GINE 与 FGCR 的 `predict_std` 本来就逐块传真实行号，
   不受影响，故未重跑。新增回归核验 `resp_predict_addresses_requested_rows`
   （与整批预测逐位一致 `1.5e-08`、对行序置换不变）。
2. **阶段 A 对照的符号约定不一致**（02:00 前后发现，早于任何结论写作）。`_paired` 的
   bootstrap 用 `RMSE(b) − RMSE(a)`，而 `delta_best/last20/mae` 用 `a − b`，导致
   `g_eta^final` 符号翻转、且 MAE 门的比较方向与协议文字相反（会把"FULL 更好"读成
   "FULL 更差"）。修复后 `cond_mae` 由 `false` 变 `true`（因为 FULL 的 MAE 本来更好），
   **分支结论不变（仍为 RESPONSE），但失败原因从"MAE 不合格"更正为"仅竞争力不合格"**，
   这一点对科学判读重要，故记入偏离。

其余为工程向修正（RESP 评价子集与训练子集分离以支持 ESOL 的 valid 片段切分、
结果目录移出 git 跟踪以避免部署冲突、运行期 ledger 写入 `results/`）。

## 10. 解释边界

* D−E 只识别**既定严格编辑图上**的残差交叉项收益。本轮**没有**随机配对/随机编辑图控制，
  因此不能声称收益特异依赖化学编辑关系，而不是一般残差耦合。
* GINE 对照只检验"是否特定结构模型专属"；它不能区分"目标更好"与"容量更大"
  （GINE 377k 参数 vs RESP 198k vs FGCR 101k）。
* 276 对只有 62 个分量，119/97/157 子集分别只有 51/45/29 个分量；<30 分量的子组只作
  低支持描述（157 组即如此）。
* 目录 2597 对**全部是单键（type 0）、非立体**切断；双键/芳香键/立体编辑未被覆盖。
* `B_ref` 来自历史 RESP/FUSION 的逐预测重放；GINE 的历史 0.6161 无 checkpoint，
  未进入参照，故"参照水平"可能仍偏松。
* 阶段 P 的配对图端点全部落在 official Train 内（1389 个端点，与 Valid420 交集为 **0**），
  所以 E/D 臂**没有**把 Valid 标签带进训练，三臂的 Valid 比较是干净的；但三臂都在同一个
  420 分子集合上做 360 epoch 的 best 选择，选模本身对三者同样偏乐观。
* `λ = 0.5` 与 `pairs_per_step = 64` 是冻结值，未做任何扫描；因此"编辑收益/分子代价"
  的折中点是否更好，本轮**未测**。
* 辅助前向的 `eval()` 模式是协议冻结项（保护 BN buffer/RNG），它同时是 DELTA 在
  official 规模上不稳定的可疑来源；本轮**没有**为救结果去改它。
