# `zinc_relation_bn_diagnostic_v1` — 固定 checkpoint 的 BN 训练/推理状态诊断

* 源：`zinc_relation_composition_probe_v1`（source commit `06cd7fd`，训练提交 `7464c0d30441`）
* 四份冻结权重：`RC_{D,S}_s0/{best,final}.pt`（supervised seed0，**无训练、无优化器、无 backward**）
* 官方 test **未构造、未加载、未评分**；valid 只做最后一次评估（不参与统计量、顺序、批次或方法选择）

## 1. 先给结论

1. **train 侧的 eval-mode 误差 100% 来自 BN 使用推理统计而不是当前 batch 统计。**
   B（batch 统计、dropout 关、不写 buffer）把四份 checkpoint 的 train MAE 全部拉回在线训练水平：
   D_best 0.023578→**0.007683**（在线 0.008735）、D_final 0.033238→**0.007610**（0.008229）、
   S_best 0.053499→**0.009829**（0.009059）、S_final 0.108899→**0.007541**（0.008440）。
   与在线的差 ≤0.0011。**T**（batch 统计 + 原 attention dropout 0.2）给出 0.0086/0.0086/0.0101/0.0084，
   比对应的 B（0.008013/0.008017/0.009685/0.007673）只高 0.0006–0.0009 ⇒ **训练态随机前向不是差异来源，只有 BN 统计来源是。**
2. **但用 train-only 重估全局统计量（C）无法恢复 train，也无法稳定恢复 valid。**
   C 的 train MAE：0.032288（D_best）、0.031793（D_final）、0.074942（S_best）、0.070034（S_final）
   ——全部仍比 B 高 3–10 倍。valid 变化是**混合方向**：−0.013069（S_final）、−0.000513（D_final）、
   +0.004754（S_best）、+0.010758（D_best）。
3. **原因不是"统计量估得不准"，而是"这个网络训练时就是逐 batch 归一化的"。**
   逐层比较（`bn_layers.json`）：11 个 BN 中有 10 个的旧 `running_mean/var` 与 train 全局矩
   几乎一致（方差比中位数 0.991–1.001，均值漂移平均 ≤0.01），只有 `layers.0.bn_h1` 明显陈旧
   （均值漂移平均 0.50、最大 1.70，方差比最低 0.45–0.46）。也就是说：把全局矩换成精确值几乎不改变
   前向函数，C 自然≈O；而 B 改变的是**函数本身**（每批自己归一化），所以只有 B 能恢复 train。
4. **对上一轮判断的影响：不改变。** 上一轮的 D/S 对比与"主体整体不如 B-R0"都是在 eval（部署）口径下
   得到的；本轮证明那个口径的 valid 数字没有被"错误统计量"系统性污染（重估后 valid 变化 −0.013…+0.011，
   且最好的 S_best 反而变差 +0.005）。BN 只解释 train/eval 不一致，不解释 valid 差距；
   **valid 差距仍是泛化差距，不是可修的推理统计损失。**
   上一轮 D→S 固定权重干预的 +0.0377 可能部分含"换规则后激活分布与旧 running stats 失配"，
   本轮按要求**没有**重做该干预，这个保留项不变。

**一句话**：这是"情形 C + E"——B 恢复 train、C 不能恢复 train，且四份 checkpoint 上 C 对 valid 的效果符号不一。

**批次上下文敏感性**：同一批分子换一个预先固定的排列（seed 20261025）后，B 的 MAE 变化只有

并不病态敏感。

## 3. 校准过程与检查（`checks.json`）

唯一方案，无扫描：一次前向用 hooks 记录真实 BN 调用顺序（**11 个**：
`layers.0..2` 各 `bn_e→bn_h1→bn_h2`，`layers.3` 只有 `bn_h1→bn_h2`；无模块被复用），
然后**按调用顺序逐个**估计：前序 BN 换成已校准统计、其余保持 O，对目标 BN 用 FP64
Chan/Welford 流式合并收集真实入口矩，写入 `running_mean=mean`、`running_var=M2/(n−1)`，
最后用完整 C 在 train 上再流一遍做自洽核对。

| 检查 | 结果 |
|---|---|
| 流式矩 vs 直接拼接求矩（不同 batch 均值/大小） | 最大差 1.8e-15 |
| BN 入口计数 = 真实 bond token / pair（padding 不计） | token 249,279；pair 6,492,991；11/11 全部匹配 |
| O 重放源报告 | 最大差 1.3e-08（四份） |
| 校准后所有 named_parameters 逐 tensor 相同 | 4/4 True（param hash 一致） |
| state_dict 差异只在 BN `running_mean/var` | 4/4 True（无其它 key） |
| 逐层自洽（完整 C 重测的全局矩 vs 写入值） | 最大均值差 9.9e-08 σ、最大相对方差差 6.3e-08 |
| C 的 eval 预测对重新分批不变 | 4.8e-07–1.4e-06 |
| 源 checkpoint / O 的 buffers 未被改写 | 4/4 True；`num_batches_tracked` 未改 |
| valid 评估前后 C 的 buffers 不变 | 4/4 True |

派生 BN buffers 与元数据保存在 `analysis/manifest.json`（源 file/state sha256、param hash、
源与派生 BN buffer hash、epoch）。**没有**把四套权重复制进 git，也没有改源 run 或源报告。

| BN | 真实条目数 | 旧/新：均值漂移(平均/最大) | 方差比 中位数 [min,max] |
|---|---|---|---|
| `layers.0.bn_e` | 6,492,991 | 0.022 / 0.063（D_best）；≤0.001（S_*） | 0.988 [0.971,1.014] |
| `layers.0.bn_h1` | 249,279 | **0.503 / 1.700**（D_best）、0.457/1.680（S_best）、0.317/0.951（S_final） | **0.976 [0.453,1.070]** |

唯一明显陈旧的是第一层的 `bn_h1`（`h_res = h + x` 的分布随训练早期漂移），其余 10 个 BN 的
running 统计与 train 全局矩在 1% 量级内一致。这直接解释了为什么 C 几乎等于 O。

## 5. 解释与边界

* **能解释**：train 侧 train-mode/eval-mode 的巨大差距（例如 S_final 从 0.109 到 0.0075）完全由
  "BN 用 batch 统计 vs 用 running 统计"决定；dropout 随机性没有贡献（T≈B）。
* **不能解释**：valid 差距。重估全局矩后 valid 变化 −0.013…+0.011、符号混合，且上一轮被选中的
  best（旧 BN 下按 valid 选出的 epoch）反而变差。**没有**"把 BN 修好就能把 valid 拉回 0.0785"这回事
  （C valid 与历史 B-R0 的差仍为 +0.0076…+0.0167）。
* **一个必须说明的耦合**：`best` 是在旧 running 统计下按 valid 选出来的，因此 C 对 `best` 与 `final`
  的作用不同（final 受益、best 受损）是**选择的产物**，不是"BN 对不同 epoch 有不同物理作用"。
  本轮**没有**、也不应该按 valid 重新选 epoch。
* **边界**：单 seed、旧 valid、四份固定权重；没有评估整条 600-epoch 轨迹在 C 下的表现，
  因此不能反推"训练时用别的归一化会更好"；也不能宣布任何跨 seed 机制收益。
* 上轮 D→S 固定权重干预（+0.0377）可能部分来自换规则后与旧 running stats 的激活失配，
  本轮按要求未重做，保留为未测项。

## 6. 下一步

**停止**。没有可修的推理统计损失：B 证明差距的来源已被完全定位（逐 batch 归一化本身是学到的函数），
C 证明"重估全局矩"不是修复手段（统计量本来就基本正确）。valid 差距属于泛化问题，本诊断没有给它
新的可操作杠杆；不建议为此加 seed、换归一化或加长日程——那是另一个假设，需要单独预注册。
