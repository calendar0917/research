## A. 核心判断

**`PARTNER_CONTENT_SUPPORTED`。把其他邻键的 learned 状态从矩块里拿掉，Locked 稳定变差
+0.0124（相对 15%），两 seed 几乎相同、CI 都不跨零、不是尾部造成。**

| 量 | 值 |
|---|---|
| `Δ = MAE(P) − MAE(B)`，seed0 | **+0.012275**，CI95 [+0.007551, +0.017181] |
| `Δ`，seed1 | **+0.012504**，CI95 [+0.007855, +0.017079] |
| `Δ`，seed-mean | **+0.012390** |
| ordinary（932）| +0.011691 / +0.013112（相对 **17.8% / 20.2%**）|
| 去 top-10 后 | +0.009431 / +0.011076 |
| tail（68）| +0.020284 / +0.004174，**两个 CI 都跨零**（不是尾部驱动）|
| any-unseen（287）| +0.022848 / +0.018984（相对 14.5% / 12.2%）|

三句话：

1. **内容重要，组织不重要。** v0 的 R/B（怎样把伙伴矩分配到关系组）差异是 −0.00026；
   本轮的 P/B（有没有伙伴内容）差异是 **+0.01239**，是前者绝对值的 48 倍。
   在**已测**的渠道里，只有"伙伴内容"被证明有量级价值；而它被如何分组（v0 的 R/B）价值为零。
2. **不是尾部效应。** tail 组两个 seed 方向都不一致且 CI 跨零；ordinary 显著为正且相对退化
   **大于**整体（17.8%/20.2% vs 14.9%/15.3%），去 top-10 后仍是 +0.0094/+0.0111。
3. **P 明显差于 DCC-L**（+0.011150/+0.010572）：BOSI-B 相对 DCC-L 的 −0.0018 优势被
   这条通道完全解释掉，甚至还差 0.009。换句话说，**BOSI 与 DCC-L 打平的全部本钱就是邻键内容**，
   而不是统计接口的形状、计数、closure 或读出结构。

## B. 设计：一个替换式 null，只改一条公式

```
B:  M[r,k] = n[r] / max(deg-1,1) * Σ_{f≠e} T_k(x[v,f])
P:  M[r,k] = n[r] * T_k(x[v,e])
```

其余逐字不变：473,889 参数、384 维矩接口、4 个关系计数、closure、`a_v/b_e/x` 的生产路径、
side/compose/reader、Fit-only masked-SSL 的 atom/bond 初始化、全部 recipe。
BOSI-B/R/DCC-L **一个都没有重训**（B/R 的 Locked 预测直接复用 v0 冻结文件，逐文件 sha256 校验）。

为什么是"替换"而不是"消融"：矩块是有形状的接口，`M≡0` 会把"没有伙伴内容"和
"side MLP 的一个 384 维输入恒零"混在一起。P 用目标半键自身内容填满同一个槽位，
从而只隔离**其他邻键的 learned 状态是否进入 M** 这一条通道。

两条必须公开的限制（`DESIGN.md` §2.2 已事前写明）：

* P 仍保留 `atom_feat` 108 维（**含半径统计**）与邻居原子 `a_u`，所以不能说"删除了全部邻域信息"。
* P 的 384 维矩块在结构上退化为 **4 个严格共线的 96 维片段**（`M[r] = n[r]·v`；已实测
  任意两组的内积误差 0.0），即整个矩块只占 **1 个 96 维方向 + 4 个计数标量**。
  所以 Δ 的含义是"伙伴内容通道**经现有接口**的价值"，其中可能混有"自内容重复是一种低效接口用法"
  这一成分。这是本轮无法再分解的，如实列出，**不做**额外实验去拆。
* P 不是 B 的严格子集：B 是均场收缩，P 是 `计数 ⊗ 自身状态` 的乘性交互。

## F. 分组：内容有用，但不特别救"未见结构"

| 组 | n | s0 Δ | s0 相对 | s1 Δ | s1 相对 |

| all | 1000 | +0.012275 | 14.9% | +0.012504 | 15.3% |
| ordinary | 932 | +0.011691 | **17.8%** | +0.013112 | **20.2%** |
| tail | 68 | +0.020284 | 6.5% | +0.004174 | 1.4% |
| low_support | 398 | +0.009897 | 16.2% | +0.012000 | 19.9% |
| any_unseen | 287 | +0.022848 | 14.5% | +0.018984 | 12.2% |
| all_supported | 315 | +0.005646 | 13.9% | +0.007236 | 17.5% |
| has_T_or_Q | 75 | +0.021582 | **28.6%** | +0.015394 | **25.2%** |
| rings_ge4 | 212 | +0.010762 | 7.7% | +0.010009 | 7.3% |

* **any-unseen 的绝对 Δ 最大（+0.0228/+0.0190）且 CI 不含 0**，但它的**相对**退化
  （14.5%/12.2%）与整体（14.9%/15.3%）持平、甚至略低。所以正确的表述是：
  **内容对未见结构同样有用，但没有额外解决未见结构泛化**。任务要求的那句
  "内容有预测价值但尚未解决未见结构泛化"在此**成立**，只是理由不是"any-unseen 没受益"，
  而是"它受益的幅度只是按比例"。
* **ordinary 的相对退化最大**（17.8%/20.2%），且 `has_T_or_Q` 子集（真正含三角/四元闭合的
  75 个分子）达到 **28.6%/25.2%**——这正是"其他邻键的内容"信息量最高的地方。
  这条与 v0 的观察方向一致：v0 里 R 臂在这个子群上比 B 差 +0.009/+0.018（真分配反而有害），
  而现在知道该子群**确实依赖伙伴内容**，只是不需要把它分组。
* **tail 与 `rings_ge4` 的 CI 都跨零**（tail n=68、rings n=212），因此结论**不是尾部驱动**。

## G. 冻结权重干预（P，best-monitor）

| run | 自身 Locked | 换用 B 统计 | 换用 R 统计 | M 置零 | side 全置零 |
|---|---:|---:|---:|---:|---:|
| P_s0 | 0.094724 | 0.310063 | 0.311649 | 0.267895 | 0.339536 |
| P_s1 | 0.093995 | 0.338432 | 0.344275 | 0.283424 | 0.323005 |

* 把 B 的统计塞进 P 的权重 → **+0.22**（v0 里把 B 的统计塞进 B→R 只 +0.010）。
  说明 P 的权重**高度专门化**于"自身内容 × 计数"这种张量形态；两臂学到的是**不相容的函数**，
  不是同一个函数的不同写法。这与 C3/C3b 的位级证据一致。
* M 置零 / side 置零的量级（0.27–0.34）与 v0 相同，属于破坏性分布外干预，
  **不能**解读为"统计值 0.2 MAE"；本轮所有定量结论只用 `P−B` 这个同分布对比。

## I. 对 v0 结论的影响

v0 的 `NO_GO` 是**针对关系分配**的，本轮把它定位得更准确：

| 问题 | 答案 | 证据 |
|---|---|---|
| 伙伴内容（`x[v,f]`, `f≠e`）进入矩块有用吗？ | **有用，+0.0124（15%），两 seed 稳定，非尾部** | P−B |
| 内容按关系组**分配**有用吗？ | **没用，−0.0003** | v0 R−B |
| 关系**计数** `n[r]` 有用吗？ | 未单独测（P 与 B 都保留 `n`）；本轮**不能**给出结论 | — |
| closure / degree / 全局 33 维有用吗？ | 未单独测 | — |

所以"BOSI 的统计主干"这个说法需要收紧：**承载信号的是 `half_encoder` 的伙伴状态及其矩汇总**，
不是"统计接口的形状"。这也直接决定了下一阶段该预训练谁（`NEXT_SSL_HYPOTHESIS.md`）。

## J. 偏差、意外与限制

1. **复用路径解析（分析侧，无结果受影响）**：v0 `freeze.json` 里记录的 checkpoint 路径是
   **相对 v0 轮次**的，`BC.resolve_path` 会解析到本轮目录；首次 `p_freeze` 因此报
   `FileNotFoundError`，改为 `_v0path()` 后通过。同一类问题还有 `historical_dcc` 实际位于
   v0 的 `summary.json` 而非 `locked_read.json`。两次失败都发生在**写出任何冻结/预测之前**，
   没有任何结果是在有 bug 的版本下产生的。
2. **`p_locked._verify` 的条目归一化**：`dccl/<seed>` 是单条记录而非字典组，首次调用抛
   `TypeError`，同样在**写出 `locked_read.json` 之前**失败；修正后完成唯一一次成功读取。
3. **事后追加的描述性统计（必须披露）**：`P−B` 的**分组 CI 与相对退化**是在看到 Locked 结果
   之后加入 `p_analyze.py` 的。它们只用于描述**事前已注册**的分组（ordinary / tail /
   low_support / any_unseen / all_supported 等），**没有**参与判决；
   判决条件与阈值在 `PROTOCOL.md` 中已于 GPU 前冻结，未改动。
4. **Monitor 噪声**：P 的 Monitor 差距在 seed1 上（+0.0169）远大于 seed0（+0.0040），
   而 Locked 差距几乎相同（+0.0125 / +0.0123）。同时 B_s1 的 Monitor（0.1224）是四个 B/R run 里
   最好的，但它的 Locked 并不更好。这说明**在 753 次 Monitor 读数上取最小值存在赢家诅咒**，
   跨 seed 比较 Monitor 不可靠；本报告的所有判决都只用**同 seed 配对的 Locked**。
5. **bootstrap 语义**：配对 bootstrap（10,000 次）只描述分子抽样，**不包含训练随机性**；
   训练随机性只能由两个 seed 的差值（+0.012275 / +0.012504，极差 0.00023）来体现。
6. **P 的接口退化**（§B 第三条）：Δ 里混有"自内容四路重复"这一低效用法的影响，无法分解。
7. **Locked 不是新盲测**：该划分历史上已被 DCC-L、ESOC、BOSI v0 读过。
8. **未测的渠道**：`n[r]` 计数、closure、degree、global33、`a_v` 的半径统计都**没有被单独消融**，
   本报告不对它们做任何价值判断。
