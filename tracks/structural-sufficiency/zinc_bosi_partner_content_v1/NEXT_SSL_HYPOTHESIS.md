# NEXT_SSL_HYPOTHESIS — 只写设计，不启动任何 GPU 作业

**状态：设计稿。本轮不训练、不预训练、不部署。** 触发条件已满足：`PARTNER_CONTENT_SUPPORTED`
且 any-unseen 未退化（`REPORT.md` §F）。但满足触发条件只意味着"这个假设有机制依据"，
不意味着"应该买"。任何执行都需要新的一轮、单独的预注册与预算。

---

## 1. 为什么现在才值得讨论

BOSI v0 已经把 **atom/bond encoder** 用 train-only masked-SSL 初始化了，但
`half_encoder`、`side`、`compose`、`reader`（合计 384,737 / 473,889 参数，81%）**只来自
共享的 seed 流**，没有任何预训练。

本轮的 Necessity 实验给出了这条假设的机制前提：把其他邻键的 learned 状态从矩块里拿掉
（P 臂），Locked 变差 **+0.01228 / +0.01250**（两 seed 同向，CI 均不跨零，相对退化 15%）。
也就是说，**承载信息的是 `half_encoder` 产生的 `x[v,f]` 及其汇总**，而这个模块恰恰是
唯一没有任何预训练信号的模块。所以"在同一个 Fit8k 无标签结构上预训练 half-edge / side /
compose"不是再加一个技巧，而是**把已经证明有用的那条通道的初始化补齐**。

## 2. 历史证据必须分成两类，不能混用

| 历史轮次 | 做了什么 | 结论 | 对本设计的约束 |
|---|---|---|---|
| `bjoc_masked_pretraining_v1` | 同一 8k Fit 分子、严格无泄漏的 15% 原子 + 15% 物理键遮蔽、全特征重建、CE(原子)+CE(键)、7,560 updates，**作为初始化** | `SELF_SUPERVISED_PRETRAINING_USEFUL`：locked-dev **−0.011984**（两 seed 同负），ordinary −0.013472，去 top-10 −0.013204；`P − C = −0.007713`（CI [−0.013252, −0.001911]）优于"多 50% 监督步"的算力对照 | **初始化阶段预训练有效**，且不是纯算力效应。这条证据支持"把同一种 pretext 扩展到新模块" |
| `bjoc_task_adaptive_ssl_v1` | 同一 SSL 任务**在监督训练期持续**做辅助 loss（每 4 个 minibatch，λ=0.1，原子重建） | `TASSL_NO_GAIN`：Monitor Δ **+0.000083**（CI [−0.00541, +0.00462]），ordinary 反而 +0.0028，算力 4.2× | **监督期持续辅助训练无收益**。因此本假设只做"初始化阶段"，**不**做 joint training / λ 搜索 / 频率搜索 |
| `zinc_bosi_architecture_v0` | BOSI 的 atom/bond encoder 正是从 `bjoc_full10k_pretraining_transfer_v1/pretrain_encoder_s{0,1}.pt` 加载 | 已冻结复用 | 新预训练必须**产出同格式的 atom/bond encoder**，否则会破坏与历史 BOSI-B/R 的可比性 |

一句话：**只买"初始化"，不买"训练期辅助"。**

## 3. 提案（若未来执行）

### 3.1 数据与遮蔽

* 只用 Fit8k 的 8,000 个分子，**不引入新分子、不引入新标签、不使用 Monitor/Locked 的任何内容**。
* 遮蔽沿用冻结的 `bjoc_masked_pretraining_v1` 生成器（15% 原子 / 15% 物理键，mask token
  原子 `27` / 键 `0`，右侧全特征重建），因为它已有 22/22 泄漏门控与 200/200 mask-swap 不变性证据。
* 关键差异：BOSI 需要**在遮蔽后的图上重建关系缓存**。若遮蔽键 = 删边（token 0），
  则 T/Q/R/N 划分与 biconnected block 必须按遮蔽图重算（纯图函数，无标签）。
  这一步要写成 `relation_arrays(masked_graph)`，并复用 v0 的同一实现以保证语义一致。
  若改用"只改键型、不删边"的遮蔽版本，则关系缓存**完全不变**，实现更简单、也更少歧义；
  **两种都要在门控里报告实际选用的那一种**，不能事后挑。

### 3.2 Pretext 目标：必须"只能通过伙伴内容求解"

这是本设计的技术核心。用 `s`（side 状态）或 `c`（bond 状态）直接预测**被遮蔽原子自身**的类型
是无意义的：`s` 的输入里就含 `a_v`，`c` 的输入里就含 `b_e`，模型抄一下 mask token 邻域即可。
所以目标必须放在**遮蔽槽位之外**：

| 头 | 目标 | 为什么只能走伙伴内容 | 梯度到达 |
|---|---|---|---|
| **H1 邻原子类型恢复** | 对目标半键 `(v,e)`，预测 **v 的另一个邻居 w 的类型**（w 为 e 之外的某个伙伴的另一端） | `a_w` 在遮蔽视图里不存在；它只出现在 `x[v,f]`（f 为 (v,w) 的半键）中，而 `M[v,e]` 是 `x[v,f]` 的唯一汇总入口；`a_v`、`b_e` 都不含它 | `half_encoder` → 间接 `atom/bond encoder` |
| **H2 邻键类型恢复** | 预测伙伴键 `f` 的键级 | 同上：`b_f` 只出现在 `x[v,f]` 里，被 `M[v,e]` 汇总 | `half_encoder`、`bond_encoder` |
| **H3 目标键类型恢复（汇总视图）** | 由 `s[v,e]` + `s[u,e]` 预测被遮蔽的 `b_e` | `s` 含 `b_e` 的 mask token，不能直接抄；必须结合 `M` 提供的"这个中心的化学环境" | `side`、`compose`、`reader`（经 c） |
| **H4 图级目标** | **待定**，见 §3.4 的泄漏审计 | 若目标是原子类型直方图，则 global33 可能已含，必须排除 | `compose`、`reader` |

H1/H2 是**唯一**能迫使 `M` 学习"邻居长什么样"的任务，也正是 Necessity 实验证明有价值的通道。
H3 用于把 `side`/`compose` 拉进梯度通路（否则它们仍然没有预训练信号）。
四头共享同一 BOSI 前向，损失 `L = Σ_h λ_h CE_h`，λ 固定为 1.0，**不做 λ 搜索**。

### 3.3 梯度必须真正到达新模块（预注册的可证伪检查）

预训练后必须报告每个模块在 pretext loss 上的梯度范数，并与监督阶段的量级对照：

* `half_encoder`：H1/H2 的**唯一**通路，梯度必须非零且在监督阶段的 0.01–1× 量级内
  （v0 实测监督期 `half_encoder` 梯度 ~0.19）。
* `side` / `compose`：只由 H3（及 H4）驱动，必须非零；若为零，说明 H3 被 mask-token 捷径
  吃掉，则该头作废并记录，不得靠调 λ 抢救。
* `reader`：只有 H4 会碰它；若无 H4，`reader` 保持 seed 初始化，报告要明确写"reader 未预训练"。

**反例检查（比"梯度非零"更强）**：把 H1 的输入从 `M[v,e]` 换成 `0`，H1 的验证 CE 必须显著上升；
把 `M[v,e]` 换成同分子的随机 `M`，CE 也必须上升。若两者都不变，说明 H1 根本没有用 `M`。

### 3.4 泄漏必须逐条堵死（本仓库已有先例，照抄其门控）

必须复用 `bjoc_masked_pretraining_v1` 的四件套并针对 BOSI 增补：

1. **mask-swap 不变性**：交换隐藏真值（原子类型/键级），所有输入**逐位不变**。≥200/200。
2. **目标不可读性**：对每个头，枚举其输入张量，证明隐藏真值不在其中；
   对 H1/H2，`M` 里只能出现 mask token，不含真值。
3. **原始特征与半径直方图**：BOSI 的 `atom_feat` 是 108 维、**含半径 2 的结构统计**。
   必须逐维审计：被遮蔽原子的类型是否出现在**该原子自己的** 108 维里（若 radius 统计
   含"自身元素计数"则泄漏），以及**邻居的** 108 维里是否含它。
   历史 `masked_feature_dependency_audit.json` 已经证明在 BJOC 特征上"遮蔽槽位 free"，
   但 BOSI 的 108 维与 BJOC 的不完全相同，**必须重跑**，不能引用。
4. **global33**：`global_feat` 的 33 维若含原子类型直方图或键级直方图，则
   `count_hidden = count_global − count_visible` 完全可算 → **H4 的图级目标不得使用任何
   被 global33 覆盖的统计**。可接受的 H4 候选：**分子中环闭合数**、**biconnected block 大小
   分布**、**直径**——这些都是图函数，遮蔽（若只改类型）不改变它们，因此既无泄漏也**无信号**；
   若遮蔽删边，它们会改变，但那时它们就是"可从可见图直接算出"的，同样无信号。
   **结论：H4 大概率不可用，应默认放弃图级头，只预训练 H1–H3，并在报告里写明
   `reader` 未被预训练。** 写这一条是为了防止未来有人用"预训练了全部模块"来夸大。
5. 预训练进程内 **`labels_read: false`**，Fit/Monitor 的 y 不得进入任何一步。

### 3.5 算力混杂（必须事前预注册对照）

历史轮次的教训：`P − C = −0.0077` 才是"预训练本身"的证据，`P − B = −0.0120` 里混了优化加速。
BOSI 的对照应当同构：

* **C 臂**：同一 BOSI-B 配置，**监督步数增加**到与"预训练 + 监督"总 wall time 相等
  （按实测比例换算，例如 47,400 → 47,400 + Δ，Δ 由预训练 wall time 决定）。
* 主对比是 `P_ssl − C`，不是 `P_ssl − B`。
* 预训练成本必须单独记账并报告（历史 7,560 updates / 两个 seed 的实际 wall time；
  BOSI 的前向更贵——`M` 的 index_add 与 chebyshev 开销——需先测一次 micro-benchmark）。
* 预算上限必须在预注册里写死；按本轮经验（单 run 0.35 A100·h），
  "两 seed 预训练 + 两 seed 对照 + 两 seed C 臂"至少 6 个轨迹，**不得**用"先跑一个看看"绕过。

## 4. 明确不提出的东西

* **不**提出训练期持续 SSL（`TASSL_NO_GAIN` 已否定该形态）。
* **不**提出 λ / 频率 / 遮蔽比例的搜索。
* **不**提出 junction token、关系分配（`R` 已被 v0 否定）、attention（内容而非组织才是关键，
  见 `zinc_bosi_architecture_v0/ATTENTION_NEXT.md` 的关闭条件）。
* **不**提出用 official valid/test 做任何选择。
* **不**在本轮启动任何 GPU 作业。

## 5. 结论

**机制上值得做，但只有一次机会。** 值得做的理由是本轮量化了内容通道的价值（+0.0124，
两 seed 稳定），而生产这个通道的模块完全没被预训练过。只有一次机会的理由是：
H1–H3 的三头设计、遮蔽图与关系缓存的一致性、108 维/global33 的泄漏审计、以及 C 臂的算力
对照，任何一项没做好，结果都无法解释。**下一轮若启动，必须先把 §3.3–§3.5 写成可证伪的门控，
再谈训练。**
