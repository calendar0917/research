## E1. "只有两个 SSL seed，所以最多两个监督 seed" —— **错误**

**原表述**（`REPORT.md` §4 第 3 点、Q5、`DECISIONS.md` D1c）：
"SSL 预训练编码器只存在 s0/s1 两份（seed 2 一跑就 FileNotFoundError），所以在不新增
SSL 预训练成本的前提下，任何单主体都不可能做到 4 seed。Q5 的唯一实验 = 先预训练
seed 2/3 的编码器。"

**证据**（`errata_audit.json → A_ssl_seed_protocol`）：`zinc_performance_search_v1`
的正式记录里，seed ≥ 2 **已经跑过并且成功**，用的就是 `pretrain_encoder_s1.pt`：

| 记录 | seed | best_valid | SSL 文件 |
|---|---:|---:|---|
| A-R0（P3Null） | 0 | 0.076224 | `pretrain_encoder_s0.pt` |
| A-R0 | 1 | 0.082276 | `pretrain_encoder_s1.pt` |
| A-R0 | **2** | 0.081998 | `pretrain_encoder_s1.pt` |
| A-R0 | **3** | 0.082546 | `pretrain_encoder_s1.pt` |
| B-R0（DCC-L） | 0 | 0.078537 | `pretrain_encoder_s0.pt` |
| B-R0 | 1 | 0.073837 | `pretrain_encoder_s1.pt` |
| B-R0 | **2** | 0.074677 | `pretrain_encoder_s1.pt` |
| B-R0 | **3** | 0.076911 | `pretrain_encoder_s1.pt` |

协议代码：`zinc_dual_channel_composer_v1/code/dcc_models.py` 与
`zinc_arch_discovery_v1/code/ad_models.py` 都写成
`ssl_path = P3_SSL_S0 if int(seed) == 0 else P3_SSL_S1`（审计输出
`dcc_ad_convention_seed0_else_s1: {dcc_models: true, ad_models: true}`）。
而 `zinc_bosi_architecture_v0/code/bosi_common.py::ssl_path(seed)` 直接用
`pretrain_encoder_s{seed}.pt`，因此**只有 BOSI 这一族的代码路径**会在 seed 2 抛
`FileNotFoundError`（审计输出 `bosi_common.ssl_path(2) = pretrain_encoder_s2.pt`）。

**更正**：
1. seed ≥ 2 是**可跑的**（≈0.37–0.40 GPU·h/run），代价不是"要新预训练"，而是
   **初始化多样性被截断**：s1 编码器被 seed 1/2/3 共用。
2. 因此"2 seed 是硬上限"作废；AAS v1 Q5 的"先预训练 seed 2/3 编码器"是**错误的
   下一步**。真正缺的不是种子数量，而是**编码器 × 监督种子的平衡设计**（见 E2）。
3. 该错误的影响范围：只影响"能不能多跑"的判断，不影响任何已记录的成绩。

## E2. "用两个 seed 的极差定义 0.006 功效地板" —— **表述错误，需拆成四个来源**

**原表述**（`REPORT.md` §4、§0）："BOSI 族 seed 极差 0.00546 > 0.003 门槛，2 seed
可分辨极限 ≈0.006"，并把它当作一个统一的"seed 噪声"数字。

这个 0.00546（BOSI-B s0=0.082405 vs s1=0.076949）**不是纯监督 seed 噪声**：
两跑的 SSL 编码器不同（s0 vs s1）。四个来源必须分开：

### (a) SSL 初始化（冻结编码器身份）
同一主体、同配方、只换编码器：

| 主体 | s0 编码器 | s1 编码器（3 个 seed 均值） | 编码器效应 | 同一编码器内的监督 seed 极差（n=3） |
|---|---:|---:|---:|---:|
| P3Null（A-R0） | 0.076224 | 0.082273 | **−0.00605** | **0.00055** |
| DCC-L（B-R0） | 0.078537 | 0.075142 | **+0.00340** | **0.00307** |

两个关键事实：
* **符号随主体翻转**（对 P3Null，s0 编码器好 0.006；对 DCC-L，s1 编码器好 0.0034）。
  所以"编码器效应"不是可加的偏置，而是**编码器 × 主体的交互**。
* **可辨识性不同**：P3Null 的 0.00605 是同一编码器内监督极差 0.00055 的 11 倍，
  基本可以认定是编码器造成的；DCC-L 的 0.00340 与其监督极差 0.00307 同量级，
  **用现有记录无法归因**。

### (b) 监督随机性（固定编码器时的初始化/批量顺序）
上表最后一列：P3Null **0.00055**（n=3），DCC-L **0.00307**（n=3）。
注意这是 3 个值的**极差**，不是 sd；用 n=3 的极差估计 sd 会偏小，且 s2/s3 与 s1
共享编码器，不能当作独立初始化样本。

### (c) CUDA / 环境非确定性（同一命令、同一 commit、同一 seed）
* `S1_s0` 两次运行（首次在写 `train.json` 时因记账 bug 崩溃，但 600 epoch 已训完，
  日志留有 `best=0.086889@369`）：0.086889 vs 0.090343 → **0.00345**。
* 本轮 pilot 的 **E_s0 重训 vs 历史锚点 `L_s0`**：两者初始状态哈希**逐位相同**
  （`f5c34c28…`）、SSL 同为 `pretrain_encoder_s0.pt`、配方相同：
  0.077049（新）vs 0.078537（历史）→ **0.00149**。

  这是本项目目前**最干净**的非确定性测量：init 与数据顺序都对齐，差异只能来自
  GPU 端（`index_add_` 原子性、cuBLAS/cuDNN 算法选择、并发负载）。
  seed 1 的同一实验给出**反号**的 0.00236（E_s1 0.076193 vs 历史 DCC-L s1 0.073837），
  两者构成一个 −0.0015/+0.0024 的漂移带，均值 +0.0004。（历史 `train.json::env`
  与本次同为 torch 2.5.1+cu124 / py3.12.14 ⇒ 不是版本差异，是运行期非确定性。）
  它同时说明：**历史上"精确复现"的 checkpoint 与新跑同一配置，本来就有 ~0.0015 的漂移**，
  所以"复用历史 E"与"重训 E"之间的差别必须显式报告（本轮已报告）。

### (d) 固定 valid 的分子杠杆（不是训练噪声，是评估属性）
valid 是固定 1,000 行，不存在"重新抽样分子"的方差；有的是**少数难行对 1000 行均值的
支配力**：row 172 单行的 |AE| 在本轮各臂间 5.03 → 13.60（对 overall 的贡献 0.0086），
固定的 B-最差 10 行 1.47 → 2.23（0.0076）。这解释为什么配对 bootstrap CI 半宽可达
0.005–0.011：那是**行异质性**，与 seed 无关。

**更正后的功效表述**（替换原文的"0.006 地板"）：

| 比较类型 | 现有一手证据 | 可分辨极限（保守） |
|---|---|---|
| 两次独立执行、完全对齐（同 init/同顺序/同编码器） | (c) 0.0015 与 0.0035 | **≳0.004** |
| 同编码器、不同监督 seed（配对） | (b) 0.0006（P3）/0.0031（DCC-L） | **≳0.004–0.006** |
| 不同编码器 | (a) 0.0034–0.0060，符号随主体翻转 | **≳0.010，且需交叉设计** |
| 任何 <0.003 的单次对比 | — | **不可解释** |

并且：**历史 DCC-L 的 4-seed 均值 0.075990 ± 0.002137 的 ±0.0021 是"同一编码器内"
的 SE**（4 个 seed 中 3 个共用 s1 编码器），它**不含编码器身份方差**；把它当作
"主体水平"的不确定度会系统性低估。P3Null 的 ±0.0030 同理。这一点不改变任何
已记录的分数，但改变"0.0035 家族差距是否显著"的结论：**在现有设计下不可判定**。

## E3. SQBC S1/S2：除池化位置外还改变了这些（因此 **S2 不能否证方向 C**）

**原表述**（`REPORT.md` §0、§3.2、§3.3）："S2 的结果（图级池化是过强而非过弱）直接
否掉了方向 C 的启动前提。"

**审计**（`errata_audit.json → D_sqbc_s1_s2_audit`，代码位置
`aas_sqbc.py::DualPoolBody.forward` + `self.pooling` 分支）。两臂共享参数、初值与
pair 编码器 Φ，但 S2 与 S1 的差别**不止池化位置**：

| # | S1 | S2 | 差别性质 |
|---|---|---|---|
| 1 | 槽位 2 = `\|P_u − P_v\|`（两端局部上下文的**对比**） | 槽位 2 = `mean_g(w²)`（**二阶矩/离散度**） | **统计量种类变了**，不是同一统计量换位置 |
| 2 | 三个槽位逐键不同 | 三个槽位**在分子内恒定** | pair 内容不再能调制单个键，退化为"图级上下文向量 + 键特征" |
| 3 | `Σ_{f≠e} w` 随局部度数增长（隐式编码多重性） | `mean over all pair rows`（**与度数无关**） | 归一化语义变了 |
| 4 | 局部计数信息通过求和幅度进入 | 计数被均值完全抹掉 | 信息量减少 |
| 5 | 与 `log1p(n_junc)` 组合表达"每个键看到多少伙伴" | 同样的输入但内容恒定 | 有效条件化改变 |

**更正**：
1. `S1 − S2 = −0.0107` 只支持一条**窄结论**："对这一份 pair 内容，把逐键局部统计换成
   同一批 pair 行的图级平均，代价 0.011"。它同时混合了(slot 语义)、(局部性)、
   (归一化)、(计数信息) 四个变化，**不能**分解出"全局池化本身"的效应。
2. **方向 C（图级/块级结构统计）未被检验**。要检验它，需要的对照是：
   * 图级统计量取自 **junction/block 对象**（不是 pair 行）；
   * 保留全部局部通道（不是把它们替换掉）；
   * 等参数、等初值、只改"统计量的汇总层级"的 matched 对照。
   本轮与历史都没有跑过这个设计（P3Null 的 `n_b · mean_g(w)` 是"全局通道 + 局部计数"，
   与本条要求最接近，但它没有 matched 的等参数局部-only 对照）。
3. 因此 `PLAN.md` 里"C 不启动"的决定仍然成立，但理由应从"被证伪"改为
   **"未被检验，且已被证明其检验需要独立设计"**。

## E4. BOSI-B 的矩块代数核对 + A0M0 的结论边界

### E4.1 代数与前向等价性（**已验证**）

代码（`bosi_models.py::BOSI.relation_stats`，arm `"B"`）：

```
vals      = chebyshev(x)                     # [H, 96] = [x, T2(x), T3(x)]
tgt_rel   = partner_tgt * N_REL + partner_rel
S[v]      = Σ_{f ≠ e} vals[partner_half[f]]           # 全部伙伴，不分关系类
n[v, r]   = #{f : rel(f) = r}
denom[v]  = max(half_deg[v] − 1, 1) = max(n_partners, 1)
M[v, r]   = (n[v, r] / denom[v]) · S[v]               # 重塑为 [H, 384]
```

**验证结果**（`errata_audit.json → C_bosi_moment_algebra`，batch=64 个分子）：

* 向量化实现 vs **逐伙伴暴力循环**：`max |Δ| = 0.0`（逐位相同）。
* **跨关系类的秩一恒等式**：在两类同时出现的半键上比较 `M[:,r]/n_r` 与 `M[:,s]/n_s`，
  `class2 vs class3`（574 个半键）、`class0 vs class3`（10）、`class1 vs class3`（2）
  的最大偏差**全部为 0.0**。
* 单类半键（2,367 个）上 `n_1 == denom` ⇒ `M_1 == S`；由 `(M, n)` 反解 `S` 的
  最大误差 `2.4e-7`（fp32 机器精度）。

**结论（本轮新增的事实）**：BOSI-B 的"384 维矩 bank"在信息量上等价于
**(S ∈ R^96, n ∈ R^4)**；四个类块是同一个 96 维向量按类占比缩放后的**广播**，
不是 384 个独立统计量。而 Side 又额外收到 `n` 本身，所以 M 里那 4 个比例因子
近乎冗余。真正的信息是 **96 维总矩 + 4 维计数**。

对照：BOSI **arm "R"** 走的是另一条分支（per-class 求和，384 个真正独立的数）。
历史结论是 R 没有稳定收益（`zinc_bosi_architecture_v0`: `NO_GO` on relation
allocation）。**即：信息更多的版本（R，384 独立数）并不比信息更少的广播版本（B，96+4）
更好。** 这条事实直接回答"要不要把 384 槽位做成最小充分统计"——槽位数从来不是杠杆。

### E4.2 A0M0 的结论边界

`A0M0` 在每个 forward 把**整块** `M`（384 维）置零（`M_abs_max == 0` 已由
`aas_checks_c.py::C9` 断言），代价 +0.00527（seed0 +0.0086 / seed1 +0.0019，
unseen +0.0187、rings≥4 +0.0165）。它支持的结论**只有一条**：

> "BOSI 的整条伙伴统计通道（`M` 的全部 384 个槽位一起）是载荷的。"

它**不支持**以下任何说法（本轮没有做、也不该被引用为已做）：
* "384 个槽位都必要" —— 没有做逐槽位/逐类留一消融；
* "矩统计不可被更小的表示替代" —— 由 E4.1，384 维本来就是 96+4 的广播，
  而"用更少/不同槽位替换"从未被测试；
* "BOSI 应保留大矩块" —— 相反应当注意的是：既然 `B` 的矩块只有 96 维有效信息、
  且 `R` 的 384 维独立信息没有带来收益，那么**"最小充分统计"路线在本轮数据下
  既未被证伪也未被支持**，它是一个尚未被正确构造的假设（详见 pilot 报告 Q4）。

**更正**：`DECISIONS.md` D3 与 `REPORT.md` §3.4 中"矩 bank 与 pair 通道互补而非替代"
的表述保留（那是消融支持的），但凡是把它读成"槽位级结论"的推论，以本节为准。
