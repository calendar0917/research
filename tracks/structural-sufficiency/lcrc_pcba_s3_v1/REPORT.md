## 1. 十六个问题

### Q1. S3 到底定义了什么？它和两跳（S1/S2）的本质区别在哪？

S3 是**一次枚举、一次编码**的显式三键简单路径集合：

```
P = { (r,u,v,x) : (r,u),(u,v),(v,x) ∈ E,  |{r,u,v,x}| = 4 }
```

每条路径记录 root `r`、mid1 `u`、mid2 `v`、end `x`、按顺序的三个键型
`(b1,b2,b3)`、两个中间原子类型 `(mid1_type, mid2_type)`、以及 `dist_G(r,x) ∈ {1,2,3}`。
它是**有根**的（按 root 连续存放，可以按 root 归约），**不含 walk**（四原子互不相同，
所以不会原路折返），**不去重、不截断、不采样**（同一终点有多条三键路线时全部保留）。

本质区别不是"更远"，而是**两跳接口在原理上看不到的局部结构**：

* 三跳环闭合（`dist=1`，三元环）；
* 四元环闭合（`dist=2`，路径从两侧包住一个环）；
* 以及 `dist=3` 时"这三个键的真实顺序与键型"，两跳邻域里没有这个有序三元组。

`analysis/structure_novelty.json` 用**精确 VF2 同构**（不是 WL 近似）在固定的
4,096 分子、无标签 Train 样本上量化了这件事：

| 量 | 值 |
|---|---:|
| 有根两球同构类 | 8,573 |
| 其中含 ≥2 个不同三球同构类的（"信息型"） | 3,780（44.1%） |
| 处于信息型类中的原子占比 | **93.5%** |
| 至少有一个信息型原子的分子占比 | **99.6%** |
| 单个两球类里最多的三球变体数 | 512 |

另外给出 6 组**跨分子、跨尺寸层**的见证对（两球同构、三球不同构，逐对 VF2 校验，
`verified_2ball_identical=true` / `verified_3ball_different=true`），以及一个合成见证：
环己烷 root 0 与正己烷 root 2 的两球同构（都是 4 原子链），三球不同构
（12 条 vs 6 条 S3 路径，`dist ∈ {1,2}` vs `dist = 3`）。

WL 签名只作为"初筛"（`hash` 分桶），报告中明确标注它**不完备**
（同签名必同构，但不同签名不必然不同构）；结论只依赖 VF2。

### Q4. 分支实现是否就是协议里那一个公式？如何证明没有偷偷做迭代消息传递？

```
z_p = SiLU( W_e a_x + E_mid1[mid1] + E_mid2[mid2] + E_bond1[b1-1] + E_bond2[b2-1] + E_bond3[b3-1] + E_dist[d-1] )
s_r = [ mean, sum/√m, log1p(m) ]            # 97 维
r_r = Linear(97,128)(s_r)                   # zero-init
h   = drop( h_raw + r_r )
```

`analysis/architecture_audit.json` 的机器校验（全部 pass）：

* **只有一个** `local`、一个 `atom_encoder`、一个 `bond_encoder`、一个 `drop`；
* **最小输入测试**：只给 S3 分支 `s3_*` 八张量 + 静态原子表示 `a`，输出与给全 batch
  时**逐位相同**（`max_abs_diff = 0.0`）——它在结构上不可能读到键、S2 路径或任何传播态；
* **零分支 = W2**：把残差强制置零，logits 与同权重 W2 的差 `2.4e-6`（CUDA 重排误差，
  容差 2e-5；CPU 上严格为 0）；
* **原子重编号**：`max|Δlogit| = 2.9e-6`（容差 2e-5，纯浮点求和顺序）；
* **原子类型/键编辑敏感性**：6/6 分子的换键型都改变了路径类型多重集，断键都改变了计数；
* **空 S3 安全**：零路径时残差恒为 0、无 NaN/Inf、无路径 root 的残差等于输出偏置；
* **批量隔离**：跨分子路径数 0，行号 ↔ 路径计数一致；
* **算子数不随路径数增长**：128 行 batch 的路径数是 8 行的 16.6 倍，单步算子调用数只
  1.35 倍（`gpu_profile.json`）——不存在逐路径 Python 循环。

### Q5. 初始化是否真的等价于"从 W2 出发但残差为零"？

`analysis/initialization_parity.json`（GPU，正式审计）：

* 两臂的 W2 子状态 **逐张量 bitwise 相同**，base state SHA-256 一致，trunk 指纹等于历史
  `5f7101a8…ef63d`；
* epoch-0 logits 与 W2 最大差 **2.86e-6**（CUDA；CPU 为 `0.0`），两臂都通过；
* 新参数由**私有 generator** 初始化（`seed·1,000,003 + offset`，S3=901、F=902），
  `initialize_new_modules` 自身不推进全局 torch RNG（断言 + 记录）；
* 零初始化输出层导致**第 1 步**只有 `out.*`（F 是 `fc2.*`）有梯度，
  **第 2 步起** `W_e` 与 6 个 embedding（F 是 `norm/fc1`）全部获得非零梯度并保持——这是
  设计决定的、可解释的行为，不是 bug；
* checkpoint → 新模型 + 新 optimizer 的 `restore` 精确恢复 state、optimizer step 与 RNG
  哈希，前向 logits 差 `0.0`。

### Q6. 参数匹配的控制臂 F 是否公平？

`H = 93`，`Δ(H) = 257H + 384`，`|24,208 − 24,285| = 77` 是全局最小（`H=94` 差 180），
相对差 **0.318%**（门限 1%）。F 的结构是 `LayerNorm → Linear(128,93) → SiLU → Linear(93,128)`
（最后一层零初始化），只看 `h_raw`，不读任何路径/键张量。两臂：

* 同一 seed、同一 batch plan（`06f43729…b6f6`，consumed prefix `1a24dfca…5f58`）、
  同一 recipe（AdamW 3e-4、warmup 1 epoch、cosine→1e-5、wd 1e-3、dropout 0.10、
  clip 5.0、FP32、原 masked BCE、40 epoch、无 early stopping）；
* `analysis/training_parity.json` 的 20 项一致性检查**全部通过**（含 epoch-0 AP 差
  1.98e-7、plan 哈希、base 指针、评估节奏、无 Test 访问）。

### Q7. S3 相对 W2 在 best-Valid AP 上提高多少？

* W2：`0.2652729` @ epoch 24（只读重放；历史记录 `0.2652733161`，差 `−4.3e-7`，
  且两个 checkpoint 的 SHA-256 与历史完全一致）；
* S3：`0.2714890397` @ **epoch 29**；
* **D_best_S3 = +0.0062157**（对历史记录值）/ **+0.0062162**（对重放值）。

逐 epoch 看这不是单点尖峰：S3 在 **38/40** 个 epoch 上高于 W2，从 epoch 24 到 40
（连续 17 个）都高于 W2 自己的 best；epoch 30–40 的最低值 `0.26759` 仍比 W2 best 高
`+0.0023`。曲线是"后段平台"，不是靠一个 epoch 的抖动。

### Q8. 机制对比（S3 − F）是多少？

**D_mech = +0.0074648**（`0.2714890 − 0.2640242`），比 D_best_S3 还大：S3 相对 W2 的
全部增益，F 一点也没有拿到；F 甚至比 W2 低 `0.00125`。S3 在 37/40 个 epoch 上高于 F。
高支持任务上 S3 − F 均值 `+0.00365`（63/107 改善）。

### Q9. 只加容量（F）有用吗？

基本没有：F best `0.2640242`（−0.00125），epoch-40 `0.2603368`（−0.00153），只有 9/40
个 epoch 高于 W2，从未超过 W2 的 best。但需要如实说明两点：

* F 在 **107 个高支持任务上其实小幅为正**（均值 `+0.00208`、中位 `+0.00243`、69/107
  改善），它的宏观损失主要来自 18 个中等支持任务（合计 −0.514，均值 `−0.0285`，其中
  task 123 一个任务就是 −0.142）；
* 所以准确的表述是："24k 通用残差容量在这个 recipe 下约等于零收益、甚至略负；而
  24k 三跳结构容量带来 +0.0062。"

### Q12. 训练/验证拟合差异说明了什么？

| 量 | W2 | S3 | F |
|---|---:|---:|---:|
| Train AP@40 | 0.58187 | 0.59094 | **0.59249** |
| Train BCE@40 | 0.02629 | 0.02485 | **0.02481** |
| Valid BCE@40 | 0.046538 | **0.046434** | 0.046691 |

F 对 Train **拟合得比 S3 更多**（AP 更高、BCE 更低），但 Valid 更差；S3 在 Valid BCE

### Q13. 模型选择协议的改变带来什么？best 与 epoch-40 是否一致？

本轮对每个 epoch（1…40）都跑一次官方 Validation，按 `argmax AP_valid`（并列取最早）
选 checkpoint；历史 W2 的 best 是按同样规则从它的历史曲线里读数（epoch 24）。
三臂的选择结果与 epoch-40 端点：

| 臂 | best epoch | best AP | AP@40 | 差（best − 40） |
|---|---:|---:|---:|---:|
| W2 | 24 | 0.2652729 | 0.2618672 | 0.003406 |
| S3 | 29 | **0.2714890** | **0.2677211** | 0.003768 |
| F | 29 | 0.2640242 | 0.2603368 | 0.003687 |

三个臂的 "best − 40" 幅度接近（≈0.0034–0.0038），说明选择规则没有对 S3 特别有利；
**两种口径下的结论一致**：S3 +0.0062（best）/ +0.0059（epoch-40），F −0.0012 / −0.0015。
best 之后（epoch 30–40）S3 的 AP 区间是 `[0.26759, 0.26885]`，没有塌陷。
按协议，**epoch-40 只作为辅助端点，不替换选中的 checkpoint**。

### Q14. 结构分支真的被模型使用了吗？

`analysis/s3_ablation.json`（诊断，非因果证明）：把训练好的 S3（epoch 29）残差强制置零，
Val AP 从 `0.2714872` 掉到 `0.2232994`，**Δ = 0.048188**；127 个任务里 120 个变差、
7 个变好，高支持任务平均掉 `0.0516`。训练后的分支强度：`‖r‖/‖h_raw‖ = 0.409`，
非零原子比例 1.0，平均每原子 3.83 条路径。

必须同时说明这个数字的**边界**：置零后的模型是 out-of-distribution 的（trunk 已经与
残差共同适应），所以 `0.2233` 不能读作"没有结构时 W2 的水平"（W2 是 0.2653）。
它只能说明：**这个分支承担了模型输出的一大部分，不是一个可以拔掉的装饰。**

### Q15. 这会不会只是噪声？单种子能说什么、不能说什么？

能说：在**完全配对的比较**（同 seed、同 batch 顺序、同 recipe、同评估器、同 GPU 型号与
driver；两臂 epoch-0 logits 差 2.9e-6）下，S3 相对 W2 的 +0.0062、相对 F 的 +0.0075，
方向一致、跨 epoch 稳定、跨任务分层稳定（107 个高支持任务 75 改善、中位 +0.0056）。

不能说：**统计显著性**。本轮只有一个种子，也没有 train-only 的重复划分；`+0.0062`
在一个 0.26 量级的指标上是 2.3% 的相对提升，但 Validation 只有 43,793 行/127 任务，
任务级方差很大（43/127 任务变差）。因此标签是"值得确认的信号"（`PROMISING_S3_SIGNAL`），
不是"已验证的泛化收益"。协议在训练前就写死了这个解释边界。

### Q16. 下一步做什么、明确不做什么？

**做（本轮不执行，已写入协议）**：在 **train-only** 上构造 scaffold-grouped 的
development split / folds（或重复的 scaffold-grouped 划分），用同一 best-Validation
选择规则**从零重训 W2 与 S3**，检查 +0.006 量级是否在划分间复现；若复现，再考虑把
三跳结构并入正式 recipe。

**不做**：不加 S4/S5、不做迭代消息传递、不放大 rank/宽度、不跑多种子 rescue、不调
超参救结果、不看 Test、不用 Test 做任何选择。

## 4. 局限（写进结论，不许事后淡化）

1. **单种子**：没有显著性声明；`+0.0062` 是点估计。
2. **Validation 选择**：best-epoch 规则用官方 Validation 选择，存在选择偏差（三个臂
   同样承受，且 best−40 的差距接近，但偏差本身不能忽略）。
3. **任务级异质性大**：43/127 任务变差；前 10 个正增益占全部正增益 50.2%。
4. **消融是 OOD 诊断**：置零后 0.2233 不能当成"没有三跳的 W2"。
5. **S3 与 F 不是"同一架构只换输入"**：S3 是"路径特征 + 单线性"，F 是"逐原子两层 MLP"；
   两者都参数匹配、零初始化、同 recipe，但归纳偏置不同。结论应表述为
   "显式三跳路径特征优于同量级通用残差容量"，而不是"三跳信息优于同架构的其它输入"。
6. **只测 PCBA 一个数据集、一个 recipe、40 epoch**；不外推到其它数据集/更长的训练。
7. **没有测 Test**：结论仅限官方 Validation，且没有用 Test 交叉验证的机会（协议如此）。
