# DECISION — path-binding sufficiency audit v1

**日期:** 2026-10-28
**判定（协议 §8 机械结果）:** `REDUNDANT / NO-GO`
**触发:** `N1_not_broad`（A_s0 只有 1/3 投影种子满足 BROAD：top-1% 原子能量占比 0.310 / 0.278 > 0.25）与 `N4_type_binding_absent`（type-only 控制在绝对尺度与自身尺度下都是 0/6 通过）。
**未触发:** `N2_D_recoverable_from_X`（最大 `R²(D|X)=0.32`，阈值 0.90）、`N3_graph_collapse`（最大 `R²(G_D|E)=0.21`，阈值 0.90）。
**GPU:** 0.0 GPU·h（本审计全部在 CPU 上完成）。

## 决定

1. **不启动 DFPB GPU 轮次。** 理由不是"T 冗余"，而是：
   - `T` 在数学上等于既有 `a,b` 的一个求和顺序（max abs diff 3.6×10⁻¹⁵，梯度恒等），DFPB 的唯一增量是对既有内容学一个二阶摘要；
   - 该摘要的残差 `D` 只有 9–13% 来自类型级结构，且在 valid 上与真实残差正交（CCA ≤0.017）——即"typed path binding"这个卖点不成立；
   - 它是否对冻结回归目标有用（L3）**完全没有测量**，本轮没有读任何 label。
2. **不把本轮记为"代数冗余"。** `D` 不在 S1/S2 里（`R²(D|X)≤0.32`，探针容量已验证），也在 h 里更不在（`R²(D|h)≈0.06`）。所以 S1/S2 不充分，只是"不充分的方式"是摘要函数，而不是编码器。
3. **关闭 `X_v→h_v` 压缩方向**（作为本问题的解）。`h` 是 `X` 的收缩，`R²(D|h) ≪ R²(D|X)`；修压缩只会丢得更多。

## 允许的唯一后续（需用户点头）

**1 GPU·h 的"第二跳组成"注入实验**，判据预先写死：

- 模型：LCRC-A 不变，仅在 `LocalContent` 输入追加 ≤160 维无参数摘要（`Σ_p b_e2`、`Σ_p K_p⊙Z_p` 等，见 `REPORT.md` §8）；
- 目标/划分/seed/epoch 预算全部沿用 LCRC-v1；
- 判别：valid MAE 相对 `0.076582` 的变化是否超过 LCRC-v1 已测的 seed 噪声（±0.002）；
- 若否 → 关闭"两跳内容组成"方向，不再讨论 DFPB；
- 若是 → 才值得讨论学习式 Q/K/V（DFPB），届时它是"已证明有用的组成的可学习版本"。

## 明确的非决定

- 没有决定"ZINC 上路径绑定无用"。只决定"这一版 DFPB（固定 `T` 定义 + 现有内容 + 现有训练配方）不值得直接买 GPU"。
- 没有声称 `D` 与 property 无关（L3 未测）。
- 没有声称不存在两个真实分子共享 `X_v` 而 `T` 不同（§3.5）。
- 没有修改 LCRC-v1 的任何权重、缓存或报告数字；`N` 分支的批次缺陷只被记录与测试，未被修复。

## 如果将来重跑本判定，先修这三处协议缺陷

1. **D1** type 控制的尺度：`D_type` 必须同时报"绝对（对真实 `T` 尺度）"与"自身尺度"，并且以**尺度无关**的关系量（`R²(D_type→D)`、CCA）作为 N4 的判据，而不是把 `D_type` 的 ρ 与真实 `D` 的阈值直接比较。
2. **D2** 一致性判据不要施加于 `R²<0` 的目标（`D_type`），或改用标准化 RMSE 的差值。
3. **D3** "top-1% 能量占比"与"结果是否由 ≤1% 原子承载"这两条在重尾但广泛的情况下互相矛盾；重跑时应先决定哪一条优先，或把 top-1% 阈值改为按化学分组（fused/ring/chain）分层报告。
