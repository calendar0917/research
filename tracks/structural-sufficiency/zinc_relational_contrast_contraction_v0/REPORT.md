## 1. 结论

按给定设计实现并跑完 24 条 CPU 门禁后，**第 11 条把它拦下**：

- `T = Zᵀ(K_R−K_D)Z` 的 **99.4%**（Frobenius 加权 **99.8%**、MLP 测试集 **99.2%**）可以被 reader
  已有的 `[Σh, Σh², 原子矩, global33, 结构质量]` 的线性函数重建；只用 `Σh` 是 97.3%，只用 `Σh²` 是 99.0%。
- 关系核相对行和 Null **唯一多出来的东西** `T_real − T_null`，同样有 **97.2%**（99.1%）可被重建。
- 预注册上限是 **0.90**。两条都失败 ⇒ 按冻结规则 STOP，不购买 GPU。

所以本轮不是"跑了但没效果"，而是**在任何训练之前就可判定：这条通道不携带 reader 拿不到的信息**。

## 3. 通过的门禁里最值得记的三条

1. **规则图上 T 不为零，且有解析见证**：三角图 `z=(1,−1,0)` → `T = 0.5`（实测 0.5，float64 误差 <1e-10）；
   C4 → 0.5；K4 团 → 2/3。所以"零行和 ⇒ 恒为零"这个直觉是错的，`B` 只杀掉常数模。
2. **核确实有结构**：`B` 的 top\|λ\| 占比均值 0.092（谱很散），`T` 与"单标量×中心化算子"版本差 36%
   —— 塌缩**不是代数的**。`T_real` 与 `T_null` 也确实不同（`‖T_R−T_D‖/‖T_R‖` 中位数 2.50）。
3. **塌缩是统计的**：共享键表征 `h` 的 participation ratio 只有 **2.57**（top-1 主成分 61%），
   逐键偏离只占 43%。零行和二次型只能看见偏离项，而当偏离落在 2.6 维、且 `B` 的 top-1 特征向量
   跨分子 `|cos|` 中位数 0.68 时，二次型就退化成 `Σh²` 的固定线性组合。

## 4. 四个问题

1. **与 DCC-L / BondRW 的前向差别**：DCC-L 是"两个 composer + 无图级二次通道"；BondRW 是"显式枚举
   键对 + 学习对称 pair 函数 `φ`"。RCC 是"一个 composer + 永不枚举键对 + 固定算子 `B` 上的 rank-16
   因子化二次型"。三者不互为重参数化。
2. **是否保留强局部表示的拟合能力**：未训练、未测。可说的只有结构层面——读出形状与 P3/DCC-L 完全相同
   （256×2），键通道是 P3 `z` 的严格超集（一阶+二阶矩，且 composer 输入含两种分组）。
3. **关系收缩是否优于行和 Null**：**没有买这次对照**。能说的更强：连 `T_real−T_null` 都 97% 可由已有块
   线性重建，所以即使 REAL>NULL 也不能归因于新的关系信息。
4. **是否有足够好的绝对性能 / 是否值得再买 seed**：都未测；且**不值得**——冗余是信息量问题，
   不是优化或样本量问题。

## 5. 披露（不软化）

1. 冗余度是在**共享初始状态**上测的（启动规则冻结为 label-free）。训练后的 composer 原则上可以让 `h`
   更高维，从而降低重建度；检验它需要被规则禁止的那次训练。**这是限制，不是免责**。
2. `z_proj` 的梯度第 2 步才非零（reader 的 T 列零初始化），与 SCM 轮冷启动同型，非 bug。
3. SSL 用的是仓库内 **full-10k 无标签** checkpoint（`006fabc1…`），不是严格 Fit8k 的
   `08e5f613…`（远端产物，重生成约 0.45 A100·h）。本轮未进训练，对判定无影响；重启必须按 Fit8k 重跑。
4. 结论只覆盖本冻结设计：rank 16、一步 lazy walk、单 composer（含分子级常数输入）、reader 已读 `Σh, Σh²`。
   **不构成**"图级二阶池化/模块度矩阵无用"的一般主张。
5. `real−null` 对照即使做出来，也只隔离核形式，不隔离"对应身份"（稀疏性/支撑集混杂仍如
   `bond_relation_attribution_v1` 所述）。

## 6. 这条结果真正约束了什么

> **图级二次通道只有在逐键内容沿关系图相干变化时才是独立信息；如果逐键内容 ≈ 一个分子共同项 +
> 2–3 维抖动，那么任何零行和的稠密二次型都会塌成 reader 已经拿到的二阶矩。**

可操作的验收条件（给下一轮）：任何"图级二阶"提案，必须在 label-free 阶段先证明
`T_real − T_null` 不能被 `[Σh, Σh²]` 线性重建——**建议门槛 ≤0.5**（本轮 0.90 太松，仍会放过一个
99% 冗余的设计）。

复现：`uv run python code/rcc_prep.py && uv run python code/rcc_cpu_checks.py && uv run python code/rcc_diag.py`
（纯 CPU，约 25 s，无 GPU、无标签、无 official valid/test）。
