# notes/ — 第一轮决策记录

## 2026-11-04 — 为什么 round-0 词表小于 512

规则是"每轮取频数最高的 512 个 token，另设 OOV 桶"。Lipophilicity 的官方 Train
只出现 48–49 种 round-0 原子签名（元素 × 电荷 × 芳香性 × 总氢 × 杂化 × CIP），
少于 512，因此保留全部。后果：不同公开划分的 round-0 块宽 49 或 50，
臂宽相差 1 列。同一划分内所有臂与样本量列完全一致，臂间对照不受影响。
没有用空列补齐到 512：那会引入 460+ 个恒零列，稀释 `colsample_bytree` 并改变
实际列采样比例——属于未经预注册的建模改动。

## 2026-11-04 — 为什么科学配置哈希排除 `stage`

freeze v1 把运行键 `stage` 算进了配置哈希，于是 `stage=freeze` 与 `stage=test`
的科学配置哈希必然不同，terminal 运行无法对齐。v2 只把 `stage` /
`rebuild_features` 视为运行选择，其余全部参与哈希。两次冻结都发生在读取任何
Test 标签之前；v1 的产物仍保留在 run `20261104-194231-436224f9`。

## 2026-11-04 — 为什么允许 Test 之后修改 `tsb_tables.py`

表 D 第一版直接用了特征 manifest 的 `coverage` 块，而该块是全体 4,200 行的聚合，
Train/Valid/Test 会得到相同数字。修正方式是从冻结的 CSR 块直接按 role 重算
OOV 与非零列比例——这是纯分析代码，不重建特征、不重训、不重评分。
`analysis/post_freeze_edits.json` 记录了旧/新哈希与"未变"核验。
代价：`test` stage 的代码哈希校验现在会（正确地）拒绝重放。
